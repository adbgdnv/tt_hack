# Проблема и ценность

## Чью боль решаем
> Любой представитель бизнеса, которому регулярно нужно принимать решение о работе с контрагентом, но у которого нет времени и/или экспертизы (юридической, финансовой, налоговой) прочитать и верно интерпретировать полный отчёт самому.

## Проблема
### Primary (цель-минимум, этот кейс) — Предприниматель S-сегмент

- Малый бизнес, оборот до ~20 млн, часто ИП / микрокомпания.
- Совмещает роли: сам и директор, и «финансист», и закупщик.
- Отрасли с активной работой с контрагентами: стройка, логистика, производство, торговля (по QA — именно материальный сектор, не IT).
- JTBD: «Мне поступило предложение (или несколько) — быстро и уверенно понять, кому можно доверять, не будучи экспертом».
- Боль: PDF сложный, экспертизы нет, при нескольких компаниях — ручное сравнение; риск пропустить стоп-сигнал.
- Триггер: новый поставщик/клиент, тендер, предоплата/товарный кредит.
### Secondary (цель-максимум, расширение) — выделенные роли в среднем бизнесе

- Финансист / фин.директор — платёжеспособность, товарный кредит.
- Юрист — правовая история, санкционные риски.
- Безопасник — судебная история, цепочки связанных лиц.
- Отдел закупок / менеджер — коммерческий потенциал, надёжность поставки.
- Руководитель — итоговый вывод.
- Для них релевантна отложенная HX (ролевая приоритизация блоков через теги).

### Out of scope (сейчас не решаем)
- Крупный бизнес с собственными комплаенс-системами.
- Проверка зарубежных контрагентов (по QA — не актуально для малого бизнеса).
- Сценарии, требующие графа связанных компаний (данных нет).

## Ценность
> Продукт превращает сложный отчёт в понятное, проверяемое решение «работать с контрагентом или нет» — за минуты и без экспертизы в финансах и праве. 
Концептуально:
- Понятно - объясняем блоки на языке предпринимателя (закрываем квалификационный разрыв).
- Быстро - сокращаем время «ИНН → решение», особенно при сравнении нескольких.
- Проверяемо - каждый вывод с ссылкой на факт, блок и дату; честно говорим «данных нет».

### Боли ЦА → Pain relievers
| Боль пользователя (из раздела о стоимости процесса)    | Как продукт её снимает                                      |
| ------------------------------------------------------ | ----------------------------------------------------------- |
| Нет юр./фин. экспертизы для интерпретации отчёта       | AI-разбор каждого блока простым языком (кнопка «AI-разбор») |
| Долго читать 10–12 блоков PDF                          | Краткий структурированный вывод + ключевые сигналы наверх   |
| Сравнение нескольких компаний — сверхлинейная нагрузка | Сравнение контрагентов в одной сессии, единый свод          |
| Риск пропустить стоп-сигнал                            | Явное выделение оснований и уровня внимания                 |
| «Нет данных» ошибочно читается как «нет риска»         | Явный блок «чего не хватает / что проверить дальше»         |
| Недоверие к ответу ИИ в чувствительных данных          | Визуальные пруфы: цифра-виджет + ссылка на блок + источник  |
| Непонятно, с чего начать диалог                        | 3 предзаготовленных вопроса для онбординга                  |

### Выгоды ЦА → Gain creators
| Желаемая выгода                                      | Как продукт её создаёт                                     |
| ---------------------------------------------------- | ---------------------------------------------------------- |
| Уверенность в решении                                | Разделение факт / интерпретация / пробел + основания       |
| Скорость без потери качества                         | Детерминированные расчёты + LLM-объяснение (меньше ошибок) |
| Ощущение контроля («я понял, а не поверил на слово») | Проверяемость и ссылки на источники                        |
| Быстрый выбор лучшего из нескольких вариантов        | Сравнительный режим                                        |
| Возможность углубиться, если нужно                   | Progressive disclosure: блок → разбор → диалог             |

### Ценность по уровням (Bain)
- Функциональная: экономит время, снижает сложность, организует информацию, снижает риск ошибки.
- Эмоциональная: снимает тревогу перед сделкой, даёт уверенность, уменьшает страх «подписать не глядя».
- Меняющая контекст (для микробизнеса): доступ к «встроенному аналитику» уровня, который малый бизнес не может позволить себе штатно (не нанимает юриста+финансиста). По сути — демократизация экспертизы.
- Последний уровень — самый сильный тезис для питча: вы даёте малому бизнесу экспертизу, которую раньше имел только крупный.


### Ценность для банка-заказчика
| Ценность для банка                              | Механизм                                                                             |
| ----------------------------------------------- | ------------------------------------------------------------------------------------ |
| Рост retention подписочного продукта            | Продукт становится удобнее конкурентов (Rusprofile/СПАРК) → меньше отток             |
| Рост вовлечённости (частота использования)      | Диалог и сравнение возвращают пользователя чаще, чем разовый PDF                     |
| Удержание внутри банковского контура            | Пользователь не уходит в специализированный внешний сервис                           |
| Дифференциация от конкурентов                   | Evidence-first диалоговый слой поверх _доверенного банковского_ сигнала              |
| Фундамент для смежных продуктов (цель-максимум) | Та же архитектура (MCP + grounding) переиспользуется под проверку сотрудника, 152-ФЗ |

## Детализация приоритетных гипотез

Гипотеза H4 (foundational). Явное состояние «недостаточно данных» позволяет агенту не выдумывать факты, при этом сохраняя способность отвечать на большинство вопросов, ответ на которые в отчёте реально есть.

Ожидаемый эффект и метрики

- Ложная уверенность (выдуманные/недоказанные факты) → близко к 0%.

- Доля корректных отказов на вопросы без данных → ≥90%.

- Покрытие: доля верных ответов на реально отвечаемые вопросы не падает более чем на 5–10% из-за «осторожности».


Как дёшево проверить

- Набор 20–30 вопросов, где часть полей намеренно вырезана из отчёта.

- Считаем три класса: верный ответ / верный отказ / ложная уверенность.

- Стоимость: пол-дня, без пользователей.

Критерии фальсификации (откат)

- Если агент выдумывает факты чаще, чем в ~5% случаев с отсутствующими данными → откат к более жёсткому grounding (ответ строго из полей tool, запрет свободной генерации фактов) или к template-based ответам.

---

Гипотеза H3 (foundational). Связка «детерминированное извлечение и расчёты + LLM-объяснение» даёт меньше числовых и фактических ошибок, чем передача всего отчёта напрямую в LLM.

Ожидаемый эффект и метрики

- Exact match по числовым ответам (выручка, коэффициенты, суммы производств) → ≥95%.

- Groundedness (каждый факт подкреплён полем) → ≥95%.

- Число внутренних противоречий в ответе → близко к 0.

- Сравнение с baseline «весь JSON в промпт»: заметно ниже error rate.

Как дёшево проверить

- 30–50 вопросов с заранее известными правильными ответами (golden set из данных).

- Прогон двух пайплайнов: (A) наш детерминированный, (B) «всё в LLM». Сравнить метрики.

- Стоимость: 1 день (основное — сборка golden set).

Критерии фальсификации (откат)

- Если детерминированный пайплайн не даёт значимого выигрыша по точности (разница в пределах погрешности) → упростить архитектуру, но сохранить расчёты чисел вне LLM (числа — самое чувствительное).

---

Гипотеза H2/H9 (core-value). Визуальные пруфы прямо в ответе (виджет с цифрой + ссылка на исходный блок + источник и дата) повышают доверие сильнее, чем текстовый ответ или простая текстовая ссылка.

Ожидаемый эффект и метрики

- Субъективная оценка доверия (шкала 1–7) выше, чем у baseline-ответа.

- Доля выводов, которые пользователь смог самостоятельно проверить по ссылке → ≥70%.

- Готовность действовать по рекомендации (declared intent) выше.

Как дёшево проверить

- A/B на 5–7 пользователях: один вариант — текстовый ответ, другой — с пруф-виджетами.

- Замер доверия + короткое интервью «что вызвало/сняло сомнения».

Критерии фальсификации (откат)

- Если пруф-виджеты не повышают доверие или перегружают интерфейс (пользователь теряется) → упростить до одной ссылки «источник» на ответ, без множественных виджетов.

---

Гипотеза H1 (core-value). Краткий структурированный разбор сокращает медианное время «ИНН → корректное решение» минимум на 50% относительно чтения PDF, не ухудшая правильность.

Ожидаемый эффект и метрики

- Медианное время до решения ↓ ≥50%.

- Правильность найденных ключевых рисков не ниже, чем при чтении PDF.

Как дёшево проверить

- 5–7 пользователей, одинаковые кейсы, split: половину решают по PDF, половину — с дашбордом.

- Замер времени + сверка найденных стоп-сигналов.

Критерии фальсификации (откат)

- Если выигрыш по времени <30% или растёт число пропущенных рисков → пересмотреть иерархию вывода (что показываем «наверху»), усилить выделение стоп-сигналов.

---

Гипотеза H7 (core-value / онбординг). Кнопка «AI-разбор» на уровне конкретного блока используется чаще и снижает барьер входа в диалог сильнее, чем пустое диалоговое окно.

Ожидаемый эффект и метрики

- Доля пользователей, дошедших до осмысленного диалога (activation) выше при наличии per-block входа.

- Первый запрос пользователя чаще осмысленный (не «пустой»/абстрактный).

Как дёшево проверить

- Прототип с двумя входами: (A) per-block кнопки, (B) только общий чат.

- Замер activation + наблюдение, с чего начинают.

Критерии фальсификации (откат)

- Если per-block вход не повышает activation или дробит внимание (пользователь не собирает картину целиком) → оставить блок-кнопки только как ярлыки, а основным сделать общий диалог с подсказками (H8).

---

Гипотеза H5 (riskiest — стратегическая ставка). Сравнение нескольких контрагентов в одном диалоге — достаточно частая и ценная задача, чтобы стать причиной возвращаться в продукт, а не только эффектной демо-функцией.

Ожидаемый эффект и метрики

- Proxy-метрики (за хакатон): подтверждённая частота сценария в интервью + намерение вернуться (declared intent) + успешность выбора лучшего варианта в прототипе.

- (Прямой retention — только гипотеза на будущее, за хакатон не измеряется — см. напряжение из раздела 6.)

Как дёшево проверить

- 5–8 problem-интервью с ЦА (как часто сравнивают? сколько компаний? как сейчас делают?).

- Лёгкий прототип выбора из 5–10 компаний, замер успешности и intent.

Критерии фальсификации (откат)

- Если сценарий сравнения оказывается редким или пользователи не связывают его с возвратом → понижаем сравнение до вторичной фичи, фокус остаётся на анализе одной компании (базовый сценарий кейса).




# Метрики продукта
## North Star Metric
> Число «результативных проверок контрагента» в неделю - проверок, доведённых до момента, когда пользователь получил понятное обоснованное заключение (просмотрел разбор/задал ≥1 уточняющий вопрос/дошёл до вывода с основаниями), в расчёте на активного пользователя. 

## Guardrails
| Guardrail                                  | Зачем                                                                                                                  |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Уровень ложной уверенности (галлюцинаций)  | Рост числа выводов не должен идти за счёт выдумок. Верхняя граница. Самый важный guardrail — прямой критерий заказчика |
| Число уточняющих вопросов на проверку      | Если растёт слишком сильно — возможно, ответы непонятны (переспрашивает), а не «глубоко вовлечён»                      |
| Доля брошенных проверок (bounce после ИНН) | Ловит случай «зашёл и не понял»                                                                                        |
| Латентность ответа                         | UX-порог; медленный ИИ убивает time-to-value                                                                           |

│

│    ├── Доля проверок с ≥1 уточняющим вопросом

│    ├── Доля проверок, дошедших до вывода с основаниями

│    └── Time-to-value: медианное время «ИНН → понятный вывод»                 [H1]

│

├── D3. КАЧЕСТВО и ДОВЕРИЕ (почему возвращаются, а не только пришли)

│    ├── Точность чисел (exact match на golden set)                            [H3]

│    ├── Доля корректных «недостаточно данных» / уровень ложной уверенности    [H4]

│    ├── Доля выводов, самостоятельно проверенных пользователем по ссылке      [H2/H9]

│    └── Субъективное доверие (CSAT/шкала 1–7)                                 [H2/H9]

│

├── D4. ГЛУБИНА и РАСШИРЕНИЕ (рост ценности на пользователя)

│    ├── Доля сессий со сравнением нескольких контрагентов                     [H5]

│    ├── Среднее число блоков, по которым запрошен AI-разбор

│    └── Доля повторно возвращающихся к диалогу по той же компании

│

└── 🎯 БИЗНЕС-РЕЗУЛЬТАТ (lagging, цель заказчика — следствие NSM)

     ├── Retention (W1/W4 возвраты)

     ├── Вовлечённость (stickiness DAU/MAU)

     └── Удержание внутри банковского контура (не ушёл к конкуренту)
