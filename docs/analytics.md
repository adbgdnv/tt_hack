# Analytics / MVP Measurement Spec

## 1. Назначение документа

Документ фиксирует, **какие продуктовые показатели собираются в MVP, из каких данных они рассчитываются и как интерпретируются**.

Эти решения зафиксированы в соответствующих документах.

Analytics отвечает только за **измеримость поведения пользователя, качества данных и использования продукта**.

---

# 2. Источники аналитики

В MVP используются два основных класса источников.

## 2.1. Raw / Data-derived

Показатели, которые рассчитываются напрямую из доступного набора данных контрагентов.

Используются для понимания:

- полноты данных;
- покрытия отдельных блоков;
- распределения типов контрагентов;
- наличия risk signals;
- доступности отдельных показателей для анализа.

Источник:

**dataset → normalized report → аналитический расчёт**

Такие метрики характеризуют данные, а не поведение пользователей.

---

## 2.2. Product Events

События, которые генерируются интерфейсом при действиях пользователя.

Используются для анализа:

- поиска;
- открытия отчёта;
- работы с блоками;
- использования AI;
- переходов между chat / block / report;
- suggested questions;
- evidence;
- feedback;
- сохранения отчёта и диалога;
- повторного использования продукта.

Источник:

**UI / interaction → event → aggregation → metric**

---

# 3. Общие требования к событиям

Каждое событие должно по возможности содержать общий набор атрибутов.

### Обязательные

- `event_name`
- `event_timestamp`
- `session_id`
- `user_id` или анонимизированный идентификатор
- `screen`
- `product_version`

### Контекстные

- `inn_hash` или иной безопасный идентификатор контрагента;
- `block_id`;
- `interaction_id`;
- `source`;
- `question_id` / `question_type`;
- `error_code`, если событие связано с ошибкой.

Сырые персональные данные и содержимое пользовательского сообщения не должны попадать в event payload без отдельного обоснования и соответствующего контроля доступа.

Для контрагента в аналитике предпочтительнее использовать обезличенный / хэшированный идентификатор, а не сам ИНН.
