# MCP-сервер: как подключить

Сервер отдаёт восемь инструментов и один ресурс поверх набора из 200
контрагентов. Логики в нём нет — только объявления; считает всё ядро,
то же самое, что стоит за веб-интерфейсом.

## Что он умеет

| Инструмент | Что отвечает |
|---|---|
| `search_counterparty` | поиск по ИНН, названию или ФИО руководителя |
| `get_counterparty_report` | отчёт целиком, поля из выгрузки |
| `assess_risk` | что сработало, что не сходится, чего оценить нельзя |
| `find_contradictions` | только противоречия между разделами |
| `compare_counterparties` | с кем осторожнее и почему, до 8 сразу |
| `get_financials` | отчётность по годам и коэффициенты |
| `look_up` | данные по теме: налоги, лицензии, учредители, закупки |
| `verify_claims` | какие числа вашего текста есть в отчётах |
| ресурс `counterparty://{inn}` | отчёт как адресуемые данные |

Ни один не возвращает числового балла компании: продукт обращает внимание
человека, а не выносит вердикт.

## Способ 1: клиент запускает сервер сам (stdio)

Так работает Claude Desktop и большинство настольных клиентов. Нужен
склонированный репозиторий и собранный набор.

```bash
git clone <репозиторий> && cd tt_hack
python3 -m venv .venv && .venv/bin/pip install -e .
python3 scripts/build_dataset.py        # 200 записей, ~3,3 МБ
```

В настройки клиента (у Claude Desktop это `claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "counterparty-checker": {
      "command": "<путь>/tt_hack/.venv/bin/python",
      "args": ["<путь>/tt_hack/src/mcp_server/server.py"],
      "env": {
        "MCP_TRANSPORT": "stdio",
        "PYTHONPATH": "<путь>/tt_hack/src",
        "DATASET_PATH": "<путь>/tt_hack/dataset/counterparties.json"
      }
    }
  }
}
```

`MCP_TRANSPORT=stdio` обязателен: по умолчанию сервер слушает сеть.

Перезапустить клиент. Инструменты появятся в списке.

## Способ 2: сервер уже поднят (streamable-http)

```bash
docker compose up -d --build mcp
scripts/mcp_probe.sh                    # ожидается «MCP жив: 8 инструментов»
```

Адрес — `http://localhost:8001/mcp`. Порт открыт только на петле машины:
в данных ФИО и личные ИНН учредителей.

Клиенту, умеющему HTTP-транспорт, достаточно этого адреса. Клиенту,
умеющему только stdio, — мост `mcp-remote`:

```json
{
  "mcpServers": {
    "counterparty-checker": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:8001/mcp"]
    }
  }
}
```

## Как проверить, что сервер отрабатывает

Три уровня, от быстрого к убедительному.

**1. Тесты — без сервера, за секунду.**

```bash
python3 -m pytest tests/test_mcp_server.py -q      # 29 тестов
```

Проверяют объявления и ответы каждого инструмента. Сервер поднимать не надо:
`mcp.tool()` регистрирует функцию и возвращает её же.

**2. Живость — сервер поднят, отвечает, набор подключён.**

```bash
scripts/mcp_probe.sh                    # ожидается «MCP жив: 8 инструментов»
```

Делает рукопожатие, читает список инструментов и зовёт один. Вызов
обязателен: сервер поднимается и без набора — читает его лениво, при первом
обращении. Без вызова «сервер отвечает» означало бы только «процесс запущен».

Голым `curl` список не получить: streamable-http требует сессию, и
`tools/list` без рукопожатия отвечает 400 «Missing session ID» — это
не поломка, а протокол.

**3. Что увидит чужой агент — настоящим MCP-клиентом.**

```bash
PYTHONPATH=src .venv/bin/python scripts/mcp_demo.py
```

Подключается как обычный клиент и печатает выхлоп четырёх инструментов:
противоречия МАКСМАРКЕТ, сравнение трёх компаний, проверку чисел и тему
«налоги». Модели здесь нет вовсе — видно ровно то, что получит агент.

## Проверить, что данные приходят из инструментов

Спросите клиента: **«что не так с ИНН 5032257375?»**

Ожидается: банкротство, конкурсный управляющий вместо директора, 2,61 млрд ₽
исков как ответчику, 54 активных производства — при том, что скоринг банка
«Низкий», а платформа ЗСК «Зелёный». Обе оценки считаются по банковским
операциям и судов не учитывают; расхождение с открытыми данными — конструкция,
а не ошибка.

Этой компании нет в памяти модели. Развёрнутый ответ означает, что он собран
инструментами.

## Выкатка на сервер

Образ собирает раннер и кладёт в реестр — на машине с 894 МБ памяти сборка
кладёт весь сервис. На сервере выкатку делает root-owned скрипт вне git-клона,
копия для истории — `deploy/bin/tt-hack-mcp-deploy`.

Один раз перед первой выкаткой:

```bash
# от root на сервере
install -m 755 -o root -g root \
  /opt/tt-hack/deploy/bin/tt-hack-mcp-deploy /usr/local/bin/tt-hack-mcp-deploy
echo 'ttdeploy ALL=(root) NOPASSWD: /usr/local/bin/tt-hack-mcp-deploy' \
  > /etc/sudoers.d/tt-hack-mcp
chmod 440 /etc/sudoers.d/tt-hack-mcp
visudo -c
```

Право выдаётся ровно на один файл. Скрипт принадлежит root и лежит вне клона:
иначе пользователь выкатки правил бы то, что запускается от root, — а это
не узкое право, а полный root.

После этого шаг выкатки добавляется в `.github/workflows/deploy.yml` рядом
с бэкендом:

```yaml
      - name: Выкатить MCP
        run: ssh "${DEPLOY_USER}@${DEPLOY_HOST}" "sudo /usr/local/bin/tt-hack-mcp-deploy ${TAG}"
```

Пока скрипт не установлен, шага в workflow быть не должно: ssh с sudo на
несуществующий файл валит выкатку целиком, вместе с бэкендом и фронтом.
