## Порядок сдачи

**Фаза 1 первая, хотя это не пользовательская история.** Пока сервер слушает
stdin, ни один инструмент нельзя вызвать снаружи — и проверять нечем.

Фазы 2–5 идут по приоритету спеки. Каждая самостоятельна: после любой из них
сервер работает и умеет на одну вещь больше.

## Что осталось

**T022 — на сервере.** Требует двух действий от владельца машины: положить
`deploy/bin/tt-hack-mcp-deploy` в `/usr/local/bin/` от root и выдать sudo
одной строкой (`docs/MCP.md`, раздел «Выкатка на сервер»). Из репозитория
это не делается — и не должно: право выдаётся ровно на один файл, и файл
лежит вне git-клона.

Шаг выкатки в `.github/workflows/deploy.yml` добавляется **после** установки
скрипта: ssh с sudo на несуществующий файл валит выкатку целиком, вместе
с бэкендом и фронтом.

**Сборка контейнера (часть T021) не проверена:** демон Docker на машине
разработки не запущен. Проверено всё остальное: оба транспорта, 29 тестов,
линтеры, разбор `docker-compose.yml` и workflow.
