# Implementation Plan: MCP-сервер

**Branch**: `015-mcp-server` | **Date**: 2026-09-06 | **Spec**: [spec.md](spec.md)

## Summary

**Инструменты.** Три отказа заменяются вызовами в ядро, добавляются три новых.
Ни одной новой бизнес-функции: всё, что нужно, уже написано и покрыто тестами.

**Транспорт.** Сервер сейчас не слушает сеть вовсе: `mcp.run()` по умолчанию
работает через stdio, а контейнер объявляет порт 8001. Отсюда и «не поднят» —
подниматься было нечему. Нужен `streamable-http`.

**Мёртвый модуль.** `core/financials.py` — три функции, каждая бросает
`NotImplementedError`, и ни одного импорта во всём проекте. Финансы давно
живут в `report.build` и `topics.look_up("финансы")`. Модуль удаляется: иначе
`get_financials` выглядит как вызов в него, а вызывает другое.

## Technical Context

**Language/Version**: Python 3.12

**Primary Dependencies**: `mcp` (FastMCP) — уже в зависимостях; новых нет

**Storage**: подготовленный набор, только чтение

**Testing**: pytest поверх объявленных инструментов; подключение к клиенту —
руками по `quickstart.md`

**Target Platform**: Linux-контейнер рядом с `api`

**Project Type**: сервис-адаптер поверх ядра

**Performance Goals**: ответ инструмента без модели — доли секунды; узкое место
одно, `repo.load`, и оно общее с `api`

**Constraints**: порт только на петле; в сервере нет бизнес-логики; в ответах
нет числового балла

**Scale/Scope**: 200 контрагентов, 8 инструментов, 1 ресурс

## Constitution Check

| Принцип | Как соблюдается |
|---|---|
| **I. Спека первична** | спека написана до кода |
| **II. Ядро не знает протоколов** | усиливается: это и есть суть фичи — сервер только объявляет имена и схемы. Проверяется тестом на отсутствие импортов `api` |
| **III. Минимальная реализация** | ни одной новой доменной функции; мёртвый модуль удаляется, а не дописывается |
| **IV. Агент обращает внимание, а не выносит вердикт** | описания инструментов несут это правило: свой промпт в чужой клиент не едет |
| **IV. Отсутствие данных — ответ** | «нет отчётности» и «показатель ноль» различаются полем, а не значением |
| **IV. Без рейтинговых таблиц** | сравнение отдаёт `Verdict` без скора — тот же, что на экране |
| **V. Отбор полей** | `slim` и `topics` уже отбирают; отчёт целиком не отдаётся никуда, кроме ресурса |

Отклонений нет.

**Structure Decision**: инструменты остаются в одном файле. Разносить восемь
объявлений по модулям значит завести структуру ради структуры: каждое
объявление — от трёх до восьми строк, и все они об одном.

## Что чем закрывается

| Инструмент | Ядро |
|---|---|
| `search_counterparty` | `repo.search` + `slim.slim` — уже так |
| `get_counterparty_report` | `repo.by_inn` + `slim.slim` — уже так |
| `assess_risk` | `report.build` → `triggers`, разделы, оценки, `gaps` |
| `compare_counterparties` | `compare.compare` + `compare.summary` |
| `get_financials` | `topics.look_up(record, "финансы")` |
| `look_up` | `topics.look_up` + `topics.catalogue` |
| `verify_claims` | `verify.check` по отчётам названных ИНН |
| `find_contradictions` | `report.build(...).triggers` |
| `counterparty://{inn}` | `repo.by_inn` + `slim.slim` |

**Почему `assess_risk` и `find_contradictions` — разные инструменты.** Разбор
рисков отвечает «что тут вообще есть», противоречия — «что не сходится между
разделами». Второе наш продукт умеет, а открытые источники нет; это стоит
называть отдельно, иначе клиентская модель до него не додумается.

**Почему `get_financials` — тема, а не свой сборщик.** Тема «финансы» уже
собирает отчётность по годам и коэффициенты словами словаря. Свой сборщик
дал бы второе представление тех же цифр — и первое же расхождение между ними
пришлось бы отлаживать.

## Риски

| Риск | Смягчение |
|---|---|
| Смена транспорта ломает работающие два инструмента | тест поднимает сервер и зовёт их |
| `0.0.0.0` внутри контейнера читается как «наружу» | наружу закрывает привязка `127.0.0.1:8001:8001`, как у `api`; проверяется снаружи машины |
| Удаление `financials.py` что-то ломает | 0 импортов, проверено `grep`; тесты подтвердят |
| Контейнер не стартует без набора | так и задумано; порядок как у `api` — сначала данные |
