# Контракт: собранный отчёт

Что сервер отдаёт интерфейсу по одному контрагенту. Тем же представлением пользуется
диалог — это обязательное свойство, а не совпадение.

---

## Ручка

`GET /counterparties/{инн}/report`

Отдаёт собранный отчёт: шапку, обе оценки риска, сводку и восемь разделов
в порядке значимости.

Существующая `GET /counterparties/{инн}` остаётся: она отдаёт отобранные поля
и нужна MCP и программному доступу. Новая ручка — представление для показа.

Контрагента нет — 404 «Компания не найдена». Промежуточных состояний между
«есть целиком» и «нет» не существует.

## Гарантии

Интерфейс вправе на них полагаться и не обязан перепроверять:

1. **Разделов всегда восемь.** У любой компании, включая предпринимателей. Меняются
   состояния и порядок, но не состав — интерфейсу не нужна ветка «а если раздела нет».
2. **Порядок уже правильный.** Разделы с сигналом идут первыми. Интерфейс отображает
   порядок, а не вычисляет его: правило «что важнее» — доменное знание.
3. **Формулировки готовы.** Каждый фактор несёт заголовок и объяснение на русском.
   Внутренних кодов в ответе нет, поэтому показать их случайно невозможно.
4. **Состояния различены.** «Сигнал», «заполнен», «пуст», «неприменим» — четыре разных
   состояния, а не признак «пусто». Различие «нет данных» и «не бывает у этой формы»
   уже сделано на сервере.
5. **Оценки риска подписаны.** Каждая несёт, чья она. Значение «нет данных для оценки»
   приходит отдельным состоянием, а не как низкий риск.

## Чего контракт не делает

- **Не выносит вердикт.** Ни «работать», ни «не работать» — этого нет в ответе,
  и появиться оно может только как решение человека.
- **Не пересчитывает оценки риска.** Они переносятся из данных.
- **Не ранжирует компании.** Значимость определяется внутри одного отчёта,
  сравнения между компаниями нет.
- **Не обращается к модели.** Отчёт собирается кодом и доступен при упавшем провайдере.

## Что это требует от интерфейса

- Показывать разделы в присланном порядке
- Пустые разделы отображать, а не скрывать: их отсутствие — информация
- Никаких привязок к конкретным компаниям в разметке
- Каждый видимый элемент управления выполняет заявленное действие
