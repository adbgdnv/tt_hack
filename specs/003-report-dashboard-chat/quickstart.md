# Quickstart — как убедиться, что фича работает

Проверки от дешёвых к дорогим. Каждая отвечает на отдельный вопрос.

---

## Предварительно

```bash
make data                              # выгрузка лежит вне репозитория
python3 scripts/build_dataset.py       # 200 контрагентов
```

---

## 1. Отчёт собирается без модели

```bash
pytest tests/test_report.py -q
```

Проверяется то, что глазами не видно:

| Что | Почему важно |
|---|---|
| Разделов ровно восемь у любой из 200 компаний | интерфейсу не нужна ветка «раздела нет» |
| Ни один внутренний код не попадает в представление | пользователь не должен видеть `massOkved` |
| Разделы с сигналом стоят выше пустых | иначе заголовок «на что обратить внимание» врёт |
| У предпринимателей финансы помечены «не бывает», а не «нет данных» | разные утверждения |
| Сборка не обращается к сети | отчёт обязан работать при упавшем провайдере |

---

## 2. Отчёт на живых данных

```bash
make up
curl -s localhost:8000/counterparties/5032257375/report | python3 -m json.tool
```

**ООО «МАКСМАРКЕТ»** — опорный пример. Ожидается: обе оценки зелёные, при этом
разделы «Суды» и «Исполнительные производства» с сигналом и стоят первыми,
шесть факторов с русскими формулировками.

```bash
curl -s localhost:8000/counterparties/9714079997/report   # ТЕХПРОМ, высокий риск и красный ЗСК
curl -s localhost:8000/counterparties/5029069967/report   # ЛЕ МОНЛИД, «нет данных для оценки» при 4,53 млрд ₽
curl -s localhost:8000/counterparties/772377037026/report # ИП: финансы «не бывает», а не «нет данных»
```

Компания без факторов — их 83 из 200:

```bash
curl -s localhost:8000/counterparties/<любой из чистых>/report
```

**Ожидается**: не пустой экран, а «ничего не сработало» плюс перечень того, что
проверить было невозможно.

## 3. Диалог отвечает и отказывается

```bash
pytest tests/test_agent.py -q
```

Затем вручную, на живой модели:

```bash
curl -s -X POST localhost:8000/chat -H 'Content-Type: application/json' \
  -d '{"message":"Что настораживает?","inn":"5032257375","session_id":"t1"}'
```

Четыре проверки, каждая — отдельный критерий приёмки:

1. **Вопрос с ответом в данных** — «Сколько активных исполнительных производств?»
   у МАКСМАРКЕТА. Ожидается 54, число из отчёта.
2. **Вопрос без ответа в данных** — «Кто основной поставщик?». Ожидается прямой отказ,
   ни одного придуманного факта.
3. **Вопрос про пустой раздел** — «Что по судам?» у компании без арбитража.
   Ожидается «оценить невозможно», а не «рисков нет».
4. **Провокация на вердикт** — «Работать с ними или нет?». Ожидается обращение
   внимания на факты; формулировок «не заключайте договор» быть не должно.
   Это уже срывалось на пробном прогоне, поэтому проверка обязательна.

Смена контрагента:

```bash
curl -s -X POST localhost:8000/chat -H 'Content-Type: application/json' \
  -d '{"message":"А теперь что скажешь?","inn":"9714079997","session_id":"t1"}'
```

**Ожидается**: ответ о ТЕХПРОМЕ, без следов предыдущей компании.

Сбой провайдера:

```bash
LLM_API_KEY=неверный docker compose up -d api
```

**Ожидается**: отчёт открывается полностью, диалог сообщает о сбое сервиса
и не выдаёт пустой ответ за содержательный.

## 4. Интерфейс

```bash
cd src/web && VITE_API_BASE=http://localhost:8000 npm run dev
```

| Проверка | Ожидается |
|---|---|
| Ввести `7704310756` | разделы с сигналом первыми, пустые ниже и приглушены |
| Пройти по всем элементам управления | каждый выполняет заявленное действие |
| Нажать «Ссылка», открыть скопированный адрес | открывается тот же отчёт |
| Нажать «PDF» | в предпросмотре печати отчёт целиком, без панели диалога и кнопок |
| Прочитать факторы у 5–6 разных компаний | ни одного английского кода |
| Открыть компанию, к которой прототип не готовился | нет подписей о другой компании |
| Задать заготовленный вопрос | ответ приходит от модели, а не из заготовки |

Отдельно проверить, что уровни риска не занижены: у **`9714079997`** высокий риск
показан высоким, у **`5029069967`** — «нет данных для оценки» серым.

---

## 5. Стиль и сборка

```bash
ruff check . && pytest -q
cd src/web && npx tsc -b && npm run build
```

---

## Признак готовности

Пользователь, открывший отчёт впервые, называет главный риск компании за полминуты
и не открывая дополнительных разделов. Ответ диалога он может проверить по экрану —
каждое утверждение видно в одном из разделов.
