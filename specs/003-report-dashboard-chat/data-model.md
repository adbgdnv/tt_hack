# Phase 1 — модель представления отчёта

То, что собирает ядро и одинаково видят интерфейс, диалог и MCP. Одно представление
на всех — иначе ответ модели разойдётся с экраном, и пользователь не сможет проверить
утверждение.

---

## Отчёт

Собирается чистой функцией от записи контрагента. Модель в сборке не участвует.

| Часть | Что несёт |
|---|---|
| **Шапка** | наименование, ИНН, форма (юрлицо или ИП), статус, дата регистрации, возраст, дата отчёта |
| **Оценки риска** | скоринг банка и уровень ЗСК — каждая с указанием, чья это оценка |
| **Сводка** | сколько разделов с сигналом, сколько чисто, сколько оценить невозможно |
| **Разделы** | восемь штук, упорядоченные по наличию сигнала |

## Раздел

Восемь разделов. Порядок задаётся не списком, а состоянием.

| Раздел | Откуда содержимое |
|---|---|
| Регистрация и реквизиты | поля записи плюс факторы разделов `license`, `site`, `filials` |
| Суды | `arbitr` плюс сводка по арбитражу и разбивка по годам |
| Исполнительные производства | `execproc` плюс число активных и сумма |
| Финансы | `finance` плюс отчётность по годам и коэффициенты |
| Реестры | `reestrs` плюс нераспознанные разделы |
| Виды деятельности | `okved` плюс основной и дополнительные ОКВЭД |
| Руководство | `manager` плюс руководитель и учредители |
| Связанные организации | `relatedComp` плюс перечень связанных |

### Состояния раздела

| Состояние | Когда | Как читается пользователем |
|---|---|---|
| **Сигнал** | есть хотя бы один негативный фактор | «вот что настораживает» |
| **Заполнен** | данные есть, негативных факторов нет | «проверено, чисто» |
| **Пуст** | данных нет | «оценить невозможно» — не «рисков нет» |
| **Неприменим** | для этой формы собственности не бывает | «у ИП такого не бывает» |

Разница между «пуст» и «неприменим» выводится из формы контрагента: у 50 предпринимателей
из 200 не бывает ни отчётности, ни учредителей, ни уставного капитала.

### Порядок

1. Разделы с сигналом — по убыванию числа и веса факторов
2. Заполненные без сигнала
3. Пустые и неприменимые

Пустые разделы **не скрываются**. «По судам данных нет» и «судов нет» — разные
утверждения, и второе мы сказать не можем.

## Фактор

| Поле | Откуда | Пример |
|---|---|---|
| Код | `code` из данных | `arbitrationDefendant` — наружу не показывается |
| Заголовок | наш словарь, 15 записей | «Выступает ответчиком в суде» |
| Объяснение | `name` из данных, как есть | «Есть арбитражные дела, в которых выступает в качестве ответчика…» |
| Раздел | `chapter` из данных | `arbitr` |
| Значимость | наш порядок | для сортировки внутри раздела |

Объяснение берётся из источника дословно: все 217 негативных факторов несут непустой
`name`. Свои формулировки исказили бы смысл и разошлись бы с тем, что пользователь
видит в интерфейсе кейсодателя.

Заголовок пишем сами только потому, что текст фактора медианно 248 символов
и в карточку не помещается.

### Значимость

Порядок задаётся частотой и тяжестью. Первые четыре кода дают 84% всех срабатываний:

| Код | Срабатываний на 200 |
|---|---:|
| `arbitrationDefendant` | 67 |
| `massOkved` | 45 |
| `executionProceedings` | 33 |
| `massAddress` | 24 |
| `fnsBlocking` | 18 |
| `profit` | 10 |
| остальные девять | 1–6 каждый |

## Оценка риска

Две независимые оценки от разных организаций, обе переносятся как есть.

| Оценка | Чья | Значения |
|---|---|---|
| Скоринг банка | банк, методология не разглашается | низкий 163 · средний 26 · высокий 5 · **нет данных 6** |
| ЗСК | платформа Банка России | зелёный 158 · жёлтый 40 · красный 2 |

«Нет данных для оценки» — отдельное состояние, не низкий риск и не высокий.
Обе оценки объясняются, но не пересчитываются.

## Диалог

| Часть | Что несёт |
|---|---|
| Сессия | идентификатор, ИНН в фокусе, ход разговора |
| Вопрос | текст от пользователя либо выбранная заготовка |
| Ответ | текст плюс перечень разделов, на которые он опирается |

Смена контрагента сбрасывает ход разговора: ответы про предыдущую компанию
в новом контексте вводят в заблуждение.

Заготовленные вопросы зависят от того, что у компании есть: спрашивать про суды
у компании без судебных дел бессмысленно.

---

## Инварианты

- Каждый показанный факт сопоставим с полем исходных данных
- Ни один внутренний код не виден пользователю ни на одной из 200 компаний
- Разделов ровно восемь у любой компании; меняются только их состояния и порядок
- Отчёт собирается без обращения к модели и не зависит от её доступности
- Представление для модели и представление для экрана — одно и то же
