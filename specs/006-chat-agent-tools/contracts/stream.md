# Контракт потока ответа

## Запрос

```
POST /chat/stream
Content-Type: application/json

{"message": "Покажи суммы исков по годам", "inn": "5032257375", "session_id": "…",
 "deal": {"side": "supplier", "scheme": "prepay", "sum": 3000000, "days": 45}}
```

`deal` необязателен — это условия сделки, выставленные в интерфейсе: роль
контрагента (`supplier` | `buyer`), схема расчётов (`prepay` | `deferral` |
`spot`), сумма и срок. Что названо в самой реплике («а если отсрочка 60 дней?»),
разбирается на сервере и переигрывает форму.

Ответ — `text/event-stream`. Обычный `POST /chat` остаётся без изменений: его
читают MCP-сервер и программные клиенты, потока они не понимают.

## События

Каждое событие — строка `event:` и строка `data:` с объектом JSON.

```
event: deal
data: {"side": "supplier", "scheme": "deferral", "sum": 3000000, "days": 60, "goal": null}

event: token
data: {"text": "54 активных "}

event: tool_start
data: {"tool": "show_chart", "title": "Строю график «Суммы исков по годам»"}

event: chart
data: {"chart": "arbitration_years", "inn": "5032257375"}

event: tool_end
data: {"tool": "show_chart", "ok": true}

event: sources
data: {"items": [{"title": "…", "url": "https://…"}]}

event: lookup
data: {"topic": "налоги", "text": "Режимы налогообложения (1):\n- …"}

event: check
data: {"total": 9, "unverified": [{"number": "48", "context": "…48 производств…"}],
       "checked": true}

event: error
data: {"detail": "Сервис разбора сейчас недоступен. Отчёт выше остаётся полным."}

event: done
data: {"sections": ["courts", "enforcement"]}
```

## Правила

- `deal` приходит **первым**, до единого токена ответа: часть условий разобрана
  из самой реплики, и пользователь должен видеть сохранённый контекст раньше,
  чем прочтёт построенный на нём ответ. Условия держатся всю сессию и переживают
  смену контрагента — они про задачу пользователя, а не про компанию.
- `error` **не** закрывает поток обрывом: уже отправленный текст остаётся у клиента.
  За `error` всегда следует `done`.
- `chart` несёт **только ключ и ИНН**. Данные графика клиент берёт из уже
  загруженного отчёта. Числа в чате не могут разойтись с дашбордом, потому что
  это буквально те же числа.
- `tool_start.title` — фраза для человека, не имя функции с аргументами.
- Разрыв соединения клиентом останавливает работу на сервере: недоеденный ответ
  продолжал бы тратить квоту, общую на всех пользователей.
- Порядок гарантирован: `tool_start` → (`chart` | `sources` | `lookup`) → `tool_end`.
- `lookup` несёт взятые по теме данные **целиком**: пользователь должен видеть
  ровно то, что увидела модель, иначе ответ станет нечем сверить.
- `check` приходит **после текста ответа и перед `done`**, один раз. Ответ уже
  прочитан к этому моменту: задерживать ради проверки первое слово значило бы
  платить за неё задержкой всего ответа. `total: 0` означает «проверять было
  нечего», а не «подтверждено».

## Прокси

Блок `/api/` требует `proxy_buffering off`. Без этого nginx копит ответ и отдаёт
целиком — снаружи неотличимо от исправного сервера без стриминга.
