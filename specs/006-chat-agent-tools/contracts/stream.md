# Контракт потока ответа

## Запрос

```
POST /chat/stream
Content-Type: application/json

{"message": "Покажи суммы исков по годам", "inn": "5032257375", "session_id": "…"}
```

Ответ — `text/event-stream`. Обычный `POST /chat` остаётся без изменений: его
читают MCP-сервер и программные клиенты, потока они не понимают.

## События

Каждое событие — строка `event:` и строка `data:` с объектом JSON.

```
event: token
data: {"text": "54 активных "}

event: tool_start
data: {"tool": "show_chart", "title": "Строю график «Суммы исков по годам»"}

event: chart
data: {"chart": "arbitration_years", "inn": "5032257375"}

event: tool_end
data: {"tool": "show_chart", "ok": true}

event: sources
data: {"items": [{"title": "…", "url": "https://…"}]}

event: error
data: {"detail": "Сервис разбора сейчас недоступен. Отчёт выше остаётся полным."}

event: done
data: {"sections": ["courts", "enforcement"]}
```

## Правила

- `error` **не** закрывает поток обрывом: уже отправленный текст остаётся у клиента.
  За `error` всегда следует `done`.
- `chart` несёт **только ключ и ИНН**. Данные графика клиент берёт из уже
  загруженного отчёта. Числа в чате не могут разойтись с дашбордом, потому что
  это буквально те же числа.
- `tool_start.title` — фраза для человека, не имя функции с аргументами.
- Разрыв соединения клиентом останавливает работу на сервере: недоеденный ответ
  продолжал бы тратить квоту, общую на всех пользователей.
- Порядок гарантирован: `tool_start` → (`chart` | `sources`) → `tool_end`.

## Прокси

Блок `/api/` требует `proxy_buffering off`. Без этого nginx копит ответ и отдаёт
целиком — снаружи неотличимо от исправного сервера без стриминга.
