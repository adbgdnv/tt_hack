## Dependencies & Execution Order

### Зависимости фаз

- **Setup (Phase 1)** → **Foundational (Phase 2)** → истории
- **US1 (Phase 3)** — первая пригодная поставка, работает без инструментов
- **US2 (Phase 4)** — нужен агент из Phase 2 и поток из US1
- **US3 (Phase 5)** — нужен хотя бы один инструмент, то есть US2. Без него нечего
  показывать, поэтому идёт следом, а не параллельно
- **US4 (Phase 6)** — снимается целиком отсутствием ключа, поэтому последняя

### Параллельные возможности

- T006, T007, T008 — разные файлы тестов
- T015, T016, T017 — один файл `tests/test_tools.py`, но независимые функции;
  писать можно вместе, коммитить одним разом
- T028, T029, T030 — тесты поиска, разные функции
- T038 и T039 — разные документы
- Фронт и сервер внутри одной истории делаются параллельно после того, как
  зафиксирован контракт событий (T005)

## Implementation Strategy

### MVP

Phase 1 → Phase 2 → Phase 3. На этом продукт уже лучше нынешнего: ответ идёт
потоком, пустоты нет. Проверяется и выкатывается отдельно.

### Дальше по срезам

1. US2 + US3 вместе — график и видимость работы. Показывать график, не показывая,
   что он строится, бессмысленно.
2. US4 — последним. Он единственный зависит от внешнего ключа и внешней сети,
   и единственный способен сломать критерий «не выдумывает». Если время кончится,
   теряется он, а не продукт.

### Что проверять на каждом чекпойнте

Не «работает ли», а **не выдумывает ли**. Первая проба этой фичи показала, что
инструмент, вернувший «показан», заставляет модель дописать выдуманную таблицу
со ссылкой на несуществующий источник. Проверка честности после каждого среза
обязательна.
