# Phase 1 — сущности

## Состояние диалога

То, из чего складывается один разговор о контрагенте.

| Часть | Что это | Где живёт |
|---|---|---|
| `messages` | история вопросов и ответов | память процесса, в рамках сессии |
| `record` | запись о компании из подготовленного набора, целиком | контекст выполнения агента |
| `report` | собранное представление отчёта — то, что на экране | строится из `record`, идёт в промпт |

**Ключевое разделение.** `record` и `report` — это одни и те же данные на разной
глубине. `report` компактен (1469 токенов) и совпадает с экраном, поэтому идёт
в промпт. `record` велик (31 000 токенов на типовой компании, до 100 000 на самой
тяжёлой) и в промпт не идёт никогда — инструменты читают его из контекста
выполнения.

История ограничена шестью парами «вопрос-ответ»: ограничение не про память,
а про токены, лимит провайдера считает вход.

Смена компании очищает историю. Ответы о предыдущей компании в новом контексте
читаются как относящиеся к текущей.

## Событие потока

Единица того, что уходит в интерфейс по мере работы агента.

| Событие | Несёт | Когда |
|---|---|---|
| `token` | фрагмент текста ответа | по мере генерации |
| `tool_start` | что делается, человеческим языком | агент начал вызов |
| `tool_end` | итог вызова или сообщение об ошибке | вызов завершился |
| `chart` | ключ графика и ИНН компании | инструмент показа графика отработал |
| `sources` | список ссылок с заголовками | инструмент поиска отработал |
| `error` | понятное сообщение о сбое | провайдер отказал, квота исчерпана |
| `done` | разделы отчёта, на которые опирается ответ | ответ дописан |

`chart` отделён от `tool_end` намеренно: интерфейс рисует график из уже
загруженного отчёта по ключу, а не из содержимого события. Так числа в чате
физически не могут разойтись с дашбордом.

`error` — это событие внутри потока, а не обрыв соединения. Уже показанный текст
остаётся на экране.

## Вид графика

Закрытый список из пяти. Модель выбирает из него и не может придумать шестой.

| Ключ | Название на экране | У скольких из 200 есть данные |
|---|---|---:|
| `plaintiff_defendant` | В какой роли судится | 160 |
| `balance` | Чем обеспечены активы | 134 |
| `revenue_assets` | Выручка и активы | 121 |
| `proceedings` | Исполнительные производства | 96 |
| `arbitration_years` | Суммы исков по годам | 61 |

Русское название — часть контракта инструмента, а не украшение: без него модель
выбирает по латинскому ключу и промахивается (см. `research.md`, п. 2).

У 22 компаний из 200 нет ни одного вида. Набор доступных для конкретной компании
известен до вызова и сообщается модели в промпте.

## Внешняя находка

Утверждение из открытого источника. Всегда отделено от фактов отчёта.

| Поле | Назначение |
|---|---|
| заголовок | что за страница |
| ссылка | чтобы пользователь мог проверить сам |
| выдержка | урезанная, бюджет токенов общий с ответом |

Не более трёх находок на запрос. Приоритет при расхождении — за отчётом,
расхождение проговаривается вслух.
