# Data Model: Живой eval-набор для агента проверки контрагентов

Формальных миграций/БД нет — это структуры данных, которыми обмениваются шаги
пайплайна (`build_cases.py` → `generated.jsonl` → `run.py` → `results/*.json`).
Источник истины — `evals/schema.py` из переносимого пакета; здесь фиксируется его
смысл на уровне спеки, чтобы `tasks.md` мог ссылаться на конкретные поля.

## Turn

Одна реплика диалога в кейсе.

| Поле | Тип | Смысл |
|---|---|---|
| `user` | `str` | Текст вопроса пользователя агенту. Непустой — иначе кейс невалиден. |

## ToolExpectation

Ожидание вызова инструмента.

| Поле | Тип | Смысл |
|---|---|---|
| `name` | `str` | Имя инструмента (например, `show_chart`). |
| `params` | `dict[str, Any]` | Ожидаемые параметры (например, `{"kind": "profit_years"}`); проверяются только перечисленные ключи. |

## Expectations

Ожидания по одному кейсу — то, из чего складывается FR-005.

| Поле | Тип | Смысл |
|---|---|---|
| `numbers` | `tuple[float, ...]` | Числа, которые должны встретиться в ответе (с допуском на округление, см. `graders/numbers.py`). |
| `required_tools` | `tuple[ToolExpectation, ...]` | Инструменты, которые обязаны быть вызваны — с точными параметрами. |
| `forbidden_tools` | `tuple[str, ...]` | Имена инструментов, вызов которых считается ошибкой. |
| `required_patterns` | `tuple[str, ...]` | Regex-паттерны, обязанные встретиться в тексте ответа. |
| `forbidden_patterns` | `tuple[str, ...]` | Regex-паттерны, встречаться не должны — их нарушение критично (см. `GradeResult.critical`). |

## EvalCase

Единица проверки — «Eval-кейс» из спеки.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | `str` | Уникальный идентификатор кейса, например `bank-unknown-<inn>`. |
| `suite` | `str` | `"regression"` или `"risk"` — соответствует FR-001. |
| `category` | `str` | Одна из девяти известных категорий (`bank_unknown`, `large_numbers`, `risk_conflict`, `not_applicable`, `empty`, `bank_scale`, `zsk_source`, `rating_methodology`, `chart_routing`). |
| `inn` | `str` | ИНН компании из `dataset/counterparties.json`, на которой строится кейс. |
| `turns` | `tuple[Turn, ...]` | Диалог, который проигрывается через агента (обычно один вопрос). |
| `expect` | `Expectations` | Ожидания, см. выше. |

**Validation rule**: `EvalCase.from_dict` требует непустые `id`, `suite`, `inn` и хотя
бы один непустой `turn` — иначе выбрасывает `ValueError` при загрузке (реализует FR-002
для отдельного кейса: лучше упасть явно на сборке, чем молча пропустить кейс).

## EvalTrace

«След прогона» из спеки — то, что реально произошло при живом вызове агента.

| Поле | Тип | Смысл |
|---|---|---|
| `answers` | `tuple[str, ...]` | Текст ответа агента на каждую реплику. |
| `tool_calls` | `tuple[ToolCall, ...]` | Фактически вызванные инструменты с параметрами. |
| `charts` | `tuple[str, ...]` | Показанные графики (ключи вида `profit_years`). |
| `sources` | `tuple[dict, ...]` | Источники, на которые сослался агент. |
| `latency_ms` | `int` | Время выполнения кейса. |
| `infra_errors` | `tuple[str, ...]` | Инфраструктурные ошибки (таймаут/429/пустой ответ модели) — непусто ⇒ кейс не участвует в оценке качества (FR-006). |

## GradeResult

Результат одной проверки (числа / policy / инструменты) над одним кейсом.

| Поле | Тип | Смысл |
|---|---|---|
| `name` | `str` | Имя грейдера: `"numbers"`, `"tools"` или `"policy"`. |
| `passed` | `bool` | Прошла ли конкретно эта проверка. |
| `score` | `float` | Доля выполненных под-условий (0.0–1.0). |
| `critical` | `bool` | Если `True` и `passed=False` — весь кейс проваливается независимо от среднего балла (FR-005: запрещённое критическое утверждение). |
| `details` | `tuple[str, ...]` | Что именно не совпало (`missing:...`, `forbidden:...`, `wrong_params:...`). |

## CaseResult

«Результат кейса» из спеки — агрегат по всем `GradeResult` одного `EvalCase`.

| Поле | Тип | Смысл |
|---|---|---|
| `case_id` | `str` | Ссылка на `EvalCase.id`. |
| `status` | `str` | `"passed"` \| `"failed"` \| `"infra_error"` — три исхода из FR-006. |
| `score` | `float \| None` | Средний балл по грейдерам; `None` при `infra_error`. |
| `grades` | `tuple[GradeResult, ...]` | Оценки по каждой проверке. |
| `infra_errors` | `tuple[str, ...]` | Копия инфраструктурных ошибок из `EvalTrace`, если были. |

**State transition**: `infra_errors` непусто → `"infra_error"` (все остальные поля
информационные, не влияют на статус); иначе — любой `critical`-грейдер провален →
`"failed"`, `score=0.0`; иначе — среднее по `grades`, `"passed"` только если **все**
грейдеры `passed=True`.

## Эталон (baseline)

Не отдельный класс — агрегат уровня прогона, который строит `evals/run.py:summarize`.

| Поле | Тип | Смысл |
|---|---|---|
| `cases` | `int` | Всего кейсов в прогоне. |
| `evaluated` | `int` | Кейсов без `infra_error`. |
| `passed` / `failed` | `int` | Среди `evaluated`. |
| `infra_errors` | `int` | Кейсов со статусом `infra_error`. |
| `pass_rate` | `float \| None` | `passed / evaluated`, `None` если `evaluated == 0`. |
| `mean_score` | `float \| None` | Средний `score` по `evaluated`. |

Этот агрегат, зафиксированный вместе с версией модели/промпта на дату прогона,
и есть «эталон» из SC-003 — сравнение следующих прогонов идёт по `pass_rate` и
составу `failed`, а не по абсолютным цифрам без контекста.
