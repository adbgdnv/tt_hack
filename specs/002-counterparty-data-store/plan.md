# Implementation Plan: Витрина данных контрагентов на сервере

**Branch**: `002-counterparty-data-store` | **Date**: 2026-09-03 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/002-counterparty-data-store/spec.md`

## Summary

Продукт показывает заготовленные примеры вместо данных: выгрузка не входит
в репозиторий, деплой переносит только собранный интерфейс, а интерфейс при
получении ответа от сервера всё равно предпочитает пример. Фича доводит настоящие
данные до экрана.

Подход: отдельный шаг сборки приводит обе выгрузки к одной форме и сохраняет
результат единым файлом. Сервер читает готовый файл при старте и отдаёт из памяти —
двести записей, около четырёх мегабайт, только чтение. Все несоответствия исходных
выгрузок разрешаются на шаге сборки, чтобы сервер получал данные, пригодные
к использованию как есть.

Ключевое решение сборки: **типы для плоской выгрузки берутся из вложенной**, а не
угадываются. Вложенная выгрузка хранит числа числами и признаки признаками, плоская —
всё текстом; схема у них общая, поэтому карта «путь → тип», снятая с первой,
применяется ко второй. Это закрывает ловушку, из-за которой признак «производство
активно» со значением `false`, прочитанный как текст, означал бы «активно».

## Technical Context

**Language/Version**: Python 3.12 (сборка набора, ядро, HTTP-сервис) · TypeScript 5.9 + React 18 (интерфейс)

**Primary Dependencies**: только стандартная библиотека для сборки набора; FastAPI + uvicorn для отдачи. Новых зависимостей фича не вводит

**Storage**: один подготовленный JSON-файл, читается в память при старте процесса. Путь задаётся переменной окружения, значение по умолчанию — внутри репозитория, но сам файл в репозиторий не попадает

**Testing**: pytest + ruff, оба уже в CI

**Target Platform**: Linux-сервер за basic-авторизацией (`/opt/tt-hack`, контейнеры `api`/`mcp`); локально — docker-compose

**Project Type**: веб-приложение — бэкенд плюс интерфейс

**Performance Goals**: отчёт по ИНН не позднее 2 секунд после ввода (SC-002); чтение набора при старте — не дольше секунды

**Constraints**: подготовленный набор не попадает ни в публичный репозиторий, ни в файлы, отдаваемые браузеру. Исходные выгрузки не изменяются — они материалы кейсодателя

**Scale/Scope**: 200 контрагентов, около 4 МБ, только чтение, набор неизменен в течение работы над продуктом

## Constitution Check

*GATE: пройден до Phase 0, перепроверен после Phase 1.*

| Принцип | Как соблюдается |
|---|---|
| **I. Спека — первична** | Спека написана и уточнена до плана; вопросы хранения и доставки закрыты явными ответами, а не догадкой |
| **II. Ядро не знает про протоколы** | Приведение к общей форме и доступ к набору живут в `src/core`. Ни `normalize`, ни `repo` не импортируют HTTP-фреймворк и MCP. Скрипт сборки лежит в `scripts/` и вызывает ядро, а не наоборот. Проверка границы сохраняется: удали `src/api` — MCP-сервер работает |
| **III. Минимальная реализация** | Новых зависимостей нет. Базы данных нет: 200 записей и точечный доступ по ИНН закрываются словарём в памяти. Два отступления от буквального минимума обоснованы ниже в Complexity Tracking |
| **IV. Требования кейсодателя — закон** | Светофоры переносятся как есть и не пересчитываются. «Данных нет» отличается от нуля на уровне представления: отсутствующее поле остаётся `None`. Для ИП разделы помечаются неприменимыми, а не пустыми. Рейтингов и вердиктов фича не добавляет |
| **V. Отбор полей** | Отбор сохраняется и применяется поверх подготовленного набора. Набор хранит полную запись, отбор происходит при отдаче — иначе разбор диалогом не сможет ответить на вопрос о поле, которого нет в сокращении |

**Результат: gate пройден.** Нарушений, требующих отказа, нет; два отступления зафиксированы и обоснованы.

**Structure Decision**: раскладка продиктована принципом II конституции и не меняется.
Доменная логика — приведение к общей форме и доступ к набору — целиком в `src/core`;
`src/api` и `src/mcp_server` остаются тонкими вызовами в ядро. Скрипт сборки живёт
в `scripts/`, потому что это инструмент разработчика, а не часть продукта: он
запускается вручную перед деплоем и в рантайме не участвует.

Подготовленный набор пишется в каталог `dataset/`, добавленный в `.gitignore`.
Каталог `data/` под него не занимается: локально это симлинк на материалы кейсодателя,
а писать в них запрещено конституцией.

## Complexity Tracking

> Отступления от буквального минимума, каждое с обоснованием.

| Отступление | Зачем нужно | Почему более простой путь отвергнут |
|---|---|---|
| В набор включаются **обе** выгрузки, хотя исходно вторую планировали отложить | Иначе половина контрагентов недоступна, а на защите вводят произвольный ИНН | Приведение плоской выгрузки уже написано и проверено на всех 200 записях в `scripts/audit_data.py`. Отложить — значит сознательно оставить сто компаний пустыми ради экономии, которой нет |
| Правится сопоставление уровней риска в интерфейсе, хотя фича про данные | До этой фичи в сопоставление не попадали настоящие значения — заготовленные примеры обходили его стороной. Включение живых данных **активирует** дефект: все уровни, включая высокий, показываются как низкий | Отложить в отдельную фичу — значит выпустить эту в состоянии, где продукт занижает риск ровно у тех компаний, ради которых он существует. Светофор по конституции источник истины; показывать его неверно хуже, чем не показывать |
