# Quickstart — как убедиться, что фича работает

Проверки идут от самой дешёвой к самой дорогой. Каждая отвечает на отдельный вопрос
и может провалиться независимо.

---

## Предварительно

Выгрузка кейсодателя лежит вне репозитория и подключается симлинком:

```bash
make data      # data → ../docs_alpha
make install   # зависимости, если ещё не поставлены
```

Проверка, что выгрузка на месте:

```bash
python3 scripts/audit_data.py --traps
```

Должно напечатать распределение оценок риска по двумстам контрагентам. Если сообщает
об отсутствии выгрузки — дальше идти незачем.

---

## 1. Собрать набор

```bash
python3 scripts/build_dataset.py
```

**Ожидается**: файл в каталоге `dataset/`, в нём двести записей, отчёт о сборке
с числом записей из каждой выгрузки — по сто.

**Провал, если**: записей меньше двухсот, или ИНН неуникальны, или скрипт молча
пропустил одну из выгрузок.

---

## 2. Проверить свойства набора

```bash
pytest tests/test_dataset_integrity.py -q
```

Тест проверяет то, что нельзя увидеть глазами:

| Что проверяется | Почему это важно |
|---|---|
| Ровно двести записей, ИНН уникальны | обе выгрузки попали в набор, дублей нет |
| Ни одна запись не состоит только из наименования и ИНН | приведение плоской выгрузки сработало — до починки таких записей было сто |
| Доля активных исполнительных производств совпадает с исходной | признак «да/нет» не перевернулся; в выгрузке 3873 таких значения |
| Все значения из обёрток читаются числами | 67 крупнейших сумм на месте, ни одна не обнулена |
| Доля заполненных разделов сопоставима между выгрузками | контрагенты неотличимы по источнику |

---

## 3. Проверить приведение и доступ по отдельности

```bash
pytest tests/test_normalize.py tests/test_repo.py -q
ruff check .
```

---

## 4. Поднять сервис и убедиться, что данные настоящие

```bash
make up
curl -s localhost:8000/health
```

**Ожидается**: сервис отвечает и сообщает число прочитанных контрагентов — двести —
и время сборки набора. Если он отвечает «жив», но молчит о данных, проверка не пройдена:
именно неразличимость «жив» и «отдаёт данные» и привела к нынешнему состоянию продукта.

### Контрагент из вложенной выгрузки

```bash
curl -s localhost:8000/counterparties/5032257375
```

ООО «МАКСМАРКЕТ». **Ожидается**: заполненные суды и исполнительные производства,
крупные суммы на месте, обе оценки риска низкая и зелёная. Это опорный пример — обе
оценки благополучны при миллиардных исках, и именно на нём видно, ради чего продукт нужен.

### Контрагент из плоской выгрузки

```bash
curl -s localhost:8000/counterparties/2466177504
```

ООО «АВТОАТЛАНТ». **Ожидается**: отчёт заполнен так же, как у предыдущего.

**Это главная проверка фичи.** До неё эта компания отдавала только наименование и ИНН —
все остальные поля приходили пустыми, и ничего при этом не падало. Если здесь снова
приходят два поля, значит приведение плоской выгрузки не работает.

### Отсутствующий контрагент

```bash
curl -s -o /dev/null -w '%{http_code}\n' localhost:8000/counterparties/0000000000
```

**Ожидается**: `404`. Не пустой отчёт, не двести — пустой отчёт неотличим
от «у компании всё чисто».

### Поиск по названию

```bash
curl -s 'localhost:8000/counterparties/search?q=МАКСМАРКЕТ'
```

**Ожидается**: непустой список с наименованием и ИНН.

## 5. Проверить в интерфейсе

```bash
cd src/web && VITE_API_BASE=http://localhost:8000 npm run dev
```

Открыть, ввести ИНН **2466177504** — контрагента из плоской выгрузки, которого заведомо
нет среди заготовленных примеров.

**Ожидается**: отчёт с настоящими данными.

**Провал, если** показан заготовленный пример: значит интерфейс по-прежнему предпочитает
пример ответу сервера.

Отдельно проверить уровни риска. Взять контрагента с высоким уровнем — их пять
из двухсот, найти можно так:

```bash
python3 -c "
import sys; sys.path.insert(0,'scripts')
from audit_data import load
for r in sum(load(), []):
    b = r.get('baseInfo') or {}
    if b.get('riskLevel') in ('HIGH','UNKNOWN'):
        print(b.get('riskLevel'), b.get('inn'), b.get('shortName'))
"
```

**Ожидается**: высокий уровень показан как высокий, «нет данных для оценки» — как
отдельное состояние.

**Провал, если** оба показаны низким риском: сопоставление уровней не исправлено,
и продукт занижает риск ровно у тех компаний, ради которых существует.

---

## 6. Перенести набор на сервер

```bash
scp dataset/<файл набора> <сервер>:<каталог набора>/
```

Затем на сервере проверить, что серверная часть видит набор — тем же обращением
к проверке живости, что и локально: число контрагентов должно быть двести.

Набор не коммитится и не попадает в файлы, отдаваемые браузеру.

---

## Признак готовности

Все шесть шагов прошли, и на вопрос «откуда взялась эта цифра в отчёте» можно ответить
указанием на поле исходной выгрузки — без чтения кода.
