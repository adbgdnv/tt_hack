# Контракт: доступ к контрагентам

Ручки, которыми пользуется интерфейс. Формы запросов и ответов сохраняются —
меняется источник данных, а не договор, поэтому интерфейс переписывать не требуется.

---

## Проверка живости

`GET /health`

Сообщает не только «сервис поднят», но и **готов ли он отвечать данными**: сколько
контрагентов прочитано и когда собран набор. Без этого «сервис жив» и «сервис отдаёт
настоящие данные» неразличимы, а это ровно то состояние, в котором продукт находится
сейчас.

Если набор недоступен, сервис до этой ручки не доходит — он не стартует.

## Поиск контрагента

`GET /counterparties/search?q=<строка>&limit=<число>`

Ищет по части наименования и по ИНН. Возвращает список кратких карточек: наименование
и ИНН, достаточные, чтобы отличить похожие компании друг от друга.

- Совпадений нет → пустой список. Это не ошибка: пустой результат означает «в данных
  таких нет», и интерфейс сообщает об этом, а не показывает сбой.
- Поиск нечувствителен к регистру.
- `limit` ограничивает выдачу; значение по умолчанию сохраняется прежним.

## Контрагент по ИНН

`GET /counterparties/{инн}`

Возвращает отчёт в отобранном виде — того объёма, что нужен интерфейсу и последующему
разбору.

- ИНН есть в наборе → отчёт со всеми доступными разделами. Контрагент отдаётся целиком,
  за одно обращение, без дозагрузки разделов по частям.
- ИНН отсутствует → **404 и «компания не найдена»**. Промежуточных состояний между
  «есть целиком» и «нет» не существует.

Отсутствующие поля отсутствуют в ответе либо приходят пустыми — но не нулями. Различение
«нет данных» и «ноль» доходит до интерфейса, иначе он покажет «рисков нет» там, где
верно «оценить невозможно».

## Что контракт требует от интерфейса

- **Данные важнее примеров.** Получив ответ сервера, интерфейс показывает его.
  Заготовленные примеры используются, только когда сервер недоступен. Сейчас порядок
  обратный: пример побеждает ответ сервера, если компания нашлась среди примеров.
- **Уровни риска сопоставляются по значениям, которые действительно приходят.**
  Действующее сопоставление не срабатывает ни на одном из четырёх значений и показывает
  низкий риск для всех, включая высокий уровень и «нет данных для оценки».
- **«Нет данных для оценки» — отдельное состояние.** Не низкий риск и не высокий.

## Чего этот контракт не касается

Разбор диалогом и программный доступ используют тот же набор через ядро, но их
поведение описывается отдельно и в эту фичу не входит.
