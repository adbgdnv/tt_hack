# Implementation Plan: Трассировка вызовов модели в LangSmith

**Branch**: `005-langsmith-tracing` | **Date**: 2026-09-04 | **Spec**: [spec.md](./spec.md)

## Summary

Поведение модели — главная неопределённость продукта, и сейчас его нельзя ни увидеть,
ни разобрать после факта. На сервере логи показывают `POST /chat 200 OK` и ничего
о содержании.

Вызов модели в коде **ровно один** — `LLMClient.ask()`. Значит «везде, где происходит
вызов LLM» это одна точка, и обернуть надо её: любой будущий вызов начнёт трассироваться
сам, без правок.

Ключевое свойство: **трассировка не может уронить продукт**. Без ключа она выключается
молча, при недоступной службе ответ пользователю не ждёт отправки, любая её ошибка
гасится. Наблюдение за системой не становится её частью.

## Technical Context

**Language/Version**: Python 3.12

**Primary Dependencies**: `langsmith` 0.12.1 — единственная новая

**Storage**: не участвует

**Testing**: pytest + ruff. Без переменной окружения `tracing_is_enabled()` возвращает
`False`, декоратор становится пустышкой — тесты не обращаются никуда сами собой

**Target Platform**: контейнер `cc-api` на сервере плюс локальный запуск

**Performance Goals**: задержка ответа не растёт заметно — отправка записей идёт фоном

**Constraints**: ключ не попадает в публичный репозиторий; отсутствие ключа
и недоступность службы не влияют на ответ

**Scale/Scope**: один вызов модели, одна новая зависимость

## Constitution Check

| Принцип | Как соблюдается |
|---|---|
| **I. Спека — первична** | Спека написана, единственная развилка закрыта ответом |
| **II. Ядро не знает про протоколы** | Обёртка ложится на `core/llm.py` — это клиент внешней службы, а не доменная логика; ни HTTP-фреймворк, ни MCP не затрагиваются |
| **III. Минимальная реализация** | Одна зависимость, один декоратор. Своей телеметрии не пишем |
| **IV. Требования кейсодателя — закон** | Поведение продукта не меняется. Пользователь трассировки не видит |
| **V. Отбор полей** | Не затрагивается: в трассировку уходит то же, что и в модель |

**Gate пройден.** Отступление — новая зависимость ради наблюдаемости — ниже.

## Project Structure

```text
src/core/
  llm.py            # + обёртка вызова и признак окружения
  config.py         # без изменений: ключ читается из окружения как остальные

.github/workflows/deploy.yml   # + LANGSMITH_* в шаг записи окружения
deploy/PREVIEW-DEPLOY.md       # + как включается и выключается
.env.example                   # + переменные с пояснением

tests/test_tracing.py          # НОВЫЙ — выключена без ключа, ошибки не всплывают
```

**Structure Decision**: обёртка живёт там же, где сам вызов. Выносить её в приложение
значило бы оставить ядро без трассировки и получить дыру ровно там, где вызов
и происходит.

## Complexity Tracking

| Отступление | Зачем нужно | Почему проще не вышло |
|---|---|---|
| Новая зависимость `langsmith` | Без неё поведение модели видно только через ручное воспроизведение, а на сервере не видно вовсе | Своя телеметрия — это своё хранилище, свой просмотр и своя отладка. Библиотека даёт это готовым и выключается одной переменной |

## Phase 0 — Research

**Как трассировка выключается.** `langsmith.utils.tracing_is_enabled()` без переменной
`LANGSMITH_TRACING` возвращает `False`, и декоратор становится пустышкой. Проверено
на установленной версии 0.12.1. Значит тесты и CI не обращаются никуда сами по себе,
без единой строки условий с нашей стороны.

**Как ошибки не всплывают.** Отправка записей идёт фоном и не блокирует вызов.
Поверх этого вызов оборачивается так, чтобы ни одно исключение трассировки
не долетело до пользователя: наблюдение не может стать причиной отказа.

**Как различить окружения.** Признак берётся из того же места, что и префикс сервиса:
на сервере задан `API_ROOT_PATH=/api`, локально пусто. Отдельной переменной не заводим —
лишняя сущность там, где различие уже выражено.

**Отвергнуто**: обёртка клиента OpenAI из библиотеки. Мы ходим к провайдеру напрямую
через `httpx`, клиента OpenAI в проекте нет, и заводить его ради трассировки значило бы
тащить зависимость потяжелее самой трассировки.

> **Пересмотрено после реализации** (коммит `85d5bb5`). Своя обёртка обошлась дороже
> расчётного: декоратор вокруг вызова плюс ручное перекладывание счётчика токенов —
> без второго записи приходили с нулями, и расход по проекту посчитать было нельзя.
> Перешли на `ChatOpenAI` из LangChain, где наблюдение встроено: обе подпорки удалены,
> поведение прежнее. Оценка «зависимость тяжелее трассировки» оказалась неверной —
> трассировка через `langsmith` и так тянулась, а `langchain-openai` добавил к образу
> сам LangChain и клиент OpenAI, 62 пакета против 57.
>
> LangGraph при этом не берём: он оркеструет граф, которого нет — один вызов,
> ноль инструментов, ноль ветвлений.

## Phase 1 — Design

**Контракт наблюдения.** Запись несёт: промпт целиком, ответ, число входных и выходных
токенов, длительность, модель, признак окружения и ИНН контрагента. Промпт уходит
как есть — включая ФИО руководителей, решение принято осознанно.

**Что остаётся неизменным.** Диалог отвечает при отсутствующем ключе, при неверном
ключе и при недоступной службе. Это три отдельные проверки, а не одна.
