# Проверка фичи

Главная проверка одна: **сервер больше не собирает**. Всё остальное — следствия.

## Срез 1 — образы появляются в реестре

После прогона конвейера:

```bash
gh api /users/adbgdnv/packages/container/tt_hack%2Fapi/versions \
  --jq '.[0:3][] | "\(.metadata.container.tags)  \(.created_at)"'
```

Ожидается образ с меткой текущего коммита и метка «последний» на нём же.

Проверка кэша: запустить конвейер второй раз без изменений — сборка должна
пройти заметно быстрее первой, ничего не пересобирая с нуля.

## Срез 2 — сервер только забирает

**Во время выкатки** держать открытым отдельный терминал:

```bash
ssh root@72.56.16.44 'while true; do uptime; sleep 5; done'
```

| Что смотреть | Было | Должно стать |
|---|---|---|
| Нагрузка | доходила до **27** | рабочие значения |
| SSH | не доходил до приветствия | подключается сразу |
| Страница | не открывалась | открывается как обычно |
| Длительность | 15–20 минут | минуты |

И параллельно — просто пользоваться продуктом: открыть компанию, задать вопрос
в диалоге. Ничего не должно замедлиться.

**Проверка, что сборки на сервере действительно нет:**

```bash
ssh root@72.56.16.44 'pgrep -af "npm|vite|docker.*build" || echo "сборки нет — верно"'
```

Запускать в момент выкатки. Любая находка означает, что переключение неполное.

**Проверка, что подъём не собирает украдкой:**

```bash
ssh root@72.56.16.44 'docker compose -f /opt/tt-hack/docker-compose.yml config | grep -A2 "image:"'
```

У `api` и `web` должно стоять имя из реестра с меткой, а не локальное имя.

## Срез 3 — откат

Взять метку предыдущего коммита и поднять на ней:

```bash
ssh root@72.56.16.44 'cd /opt/tt-hack && TAG=<прошлый-коммит> docker compose pull && \
  TAG=<прошлый-коммит> docker compose up -d --no-build'
```

Ожидается: поднимается меньше чем за две минуты, ничего не собирается, сервис
отвечает прежней версией.

## Что не должно сломаться

Перенос обязан сохранить всё, что накоплено прошлыми поломками:

| Проверка | Как убедиться |
|---|---|
| Бэкенд выкатывается **до** фронта | порядок шагов в логе выкатки |
| Не поднявшийся контейнер откатывается | подставить заведомо битую метку и посмотреть, что сайт живой |
| Проверяются и статика, и API | `curl localhost:5173/` и `localhost:5173/api/health` |
| Здоровье фронта — по IPv4 | контейнер `healthy`, а не `unhealthy` при рабочей странице |

Последнее — недавняя поломка: в образе имя `localhost` резолвится только в IPv6,
а nginx слушает IPv4, и проверка отвечала «connection refused» на исправном
контейнере.

## Версия на сервере

Должна быть видна, не заходя на сервер:

```bash
gh run list --limit 1 --workflow "Deploy preview" --json displayTitle,headSha
```

И в итоге выкатки — метка, по которой образ находится в реестре.

## Продуктовый код

```bash
git diff --stat main -- src/ tests/
```

Должно быть **пусто**. Если здесь что-то есть — фича вышла за свои рамки.
