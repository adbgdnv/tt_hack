# Контракт: описания графиков в отчёте

Описания приходят вместе с собранным отчётом, внутри разделов. Отдельной ручки нет:
график без своего раздела не имеет смысла, а лишний запрос замедлил бы отчёт.

---

## Гарантии

Интерфейс вправе на них полагаться:

1. **Описание существует только когда данных достаточно.** Ряд с одной точкой,
   пустой ряд, отсутствующая величина — до интерфейса не доходят. Ветки «а вдруг
   данных мало» не нужно: решение принято на сервере.
2. **Подписи оси и значения соответствуют один к одному.** Пропуск в ряду означает
   отсутствие года, а не ноль.
3. **Заголовки готовы к показу.** Формулировать нечего.
4. **Основание приложено** — поля отчёта, из которых построен график.
5. **Числа совпадают с фактами раздела.** Выручка на графике и выручка в списке фактов
   это одно значение, а не два независимо посчитанных.

## Чего контракт не делает

- **Не задаёт отрисовку.** Ни цветов, ни размеров, ни библиотеки — это забота
  интерфейса. Описание говорит, что показать.
- **Не сравнивает компании.** Общей шкалы между контрагентами нет: сравнение
  не входит в поставку, а ранжирование кейсодателю не нужно.
- **Не обращается к модели.** Графики доступны при упавшем провайдере.
- **Не строит график из одной точки** ни при каких данных.

## Что требуется от интерфейса

- Рисовать в том разделе, к которому график принадлежит
- Показывать значения подписями: на печати нет наведения мышью
- Оставлять числа рядом доступными — график даёт форму, число даёт точность
- Не пытаться дорисовать отсутствующие точки: пропуск это отсутствие данных
