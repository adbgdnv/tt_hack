# Tasks: Графики в отчёте о контрагенте

**Input**: Design documents from `/specs/004-report-charts/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/)

**Tests**: включены. Правила достаточности данных проверяются только прогоном
по всем двумстам компаниям: график из одной точки выглядит как обычный график,
а пустая рамка — как поломка вёрстки. Глазами это ловится случайно.

**Organization**: истории разложены по разделам отчёта. Каждая доводит до конца графики
одного раздела и проверяется независимо: сломанный график в «Финансах» никак
не влияет на «Суды».

## Format: `[ID] [P?] [Story] Description`

- **[P]**: можно делать параллельно — разные файлы, нет незакрытых зависимостей
- **[Story]**: к какой истории относится задача (US1, US2, US3)
- В описании указан точный путь к файлу

## Path Conventions

`src/core/` — сборка описаний, `src/web/` — отрисовка, `tests/` в корне.
Раскладка из [plan.md](./plan.md).

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: без зависимостей
- **Foundational (Phase 2)**: после Setup. **Блокирует все истории**
- **US1, US2, US3**: каждая после Foundational, друг от друга не зависят
- **Polish (Phase 6)**: после поставленных историй

### User Story Dependencies

Истории разложены по разделам отчёта, поэтому независимы по построению: US1 трогает
«Финансы», US2 — «Суды», US3 — «Исполнительные производства». Пересечение только
в общей обёртке отрисовки, готовой в фундаменте.

US2 добавляет столбцы, US1 — линии. Порядок между ними свободный, но кто идёт первым,
тот и делает вторую форму в обёртке дешевле для следующего.

### Within Each User Story

- Сборка описания в ядре перед отрисовкой в интерфейсе
- Тесты пишутся до реализации и должны падать до неё
- История закрывается целиком до перехода к следующей

### Parallel Opportunities

- T002 параллельна T001
- В фундаменте: T005 параллельна T003–T004; T007 параллельна T003–T006, это интерфейс
- В каждой истории тестовая задача параллельна интерфейсным
- **Все три истории идут параллельно после фундамента** — разные разделы, разные файлы описаний
- В Polish: T030 и T031 параллельны

## Implementation Strategy

### MVP — Setup, фундамент и US1

Финансовая динамика — то, ради чего графики просили: «Выручка 116 млрд ₽» без
предыдущих лет не говорит ничего. Показывать можно уже здесь.

### Инкрементальная поставка

1. Setup + Foundational → описание доезжает, обёртка рисует
2. US1 → динамика и структура в «Финансах» → **MVP**
3. US2 → роль в судах → показывать
4. US3 → производства и отсутствие пустых рамок → показывать
5. Polish → печать, документация, контекст модели

### Порядок при нехватке времени

**US2 дешевле US1 и покрывает больше компаний** — 160 против 121, а форма проще:
два столбца против линий с двумя шкалами. Если время кончается, начинать стоит с неё,
несмотря на порядок номеров.

US3 резать нельзя целиком: правила достаточности лежат в фундаменте, и без задачи
про объяснение отсутствия появятся пустые рамки — они хуже, чем отсутствие графиков
вовсе.
