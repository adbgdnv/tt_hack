# Контракт: триггеры

## В отчёте

`Report` получает поле `triggers` — список сработавшего, уже упорядоченный
по значимости. Пустой список означает «противоречий не найдено» и на экране
выражается словами, а не пустотой.

```
triggers: [
  {
    key: "status_note",
    title: "Статус с оговоркой",
    explanation: "Компания числится действующей, но у статуса есть приписка",
    evidence: ["Признано несостоятельным (банкротом), открыто конкурсное производство"],
    section: "registration",
    weight: 5,
    tags: ["надёжность"]
  }
]
```

Поле `fields` в интерфейс **не уходит**: пути внутри данных пользователю
показывать нельзя (FR-013).

## В промпте агента

Триггеры идут отдельным блоком после разделов, до правил ответа:

```
ПРОТИВОРЕЧИЯ В ДАННЫХ
Найдены сами, не из готовых признаков источника. Каждое можно проверить
в названном разделе.
- Статус с оговоркой (раздел «Регистрация и реквизиты»): компания числится
  действующей, но у статуса есть приписка — признано несостоятельным (банкротом)…
```

Формулировки обращают внимание, а не выносят вердикт: «обратите внимание»,
«стоит уточнить», без «не работайте с ними» — принцип IV конституции.

## Порядок по вопросу

`GET /counterparties/{inn}/report` отдаёт порядок по значимости.
Вопрос в `/chat` и `/chat/stream` может его переставить: намерение выводится
из текста вопроса правилами, триггеры с совпавшими тегами поднимаются наверх.

Состав не меняется никогда.

## Словарь

`GET /counterparties/{inn}/report` в описаниях графиков отдаёт `source` уже
словами. Путь внутри данных остаётся в `fields` триггеров — для тестов
и будущего подбора контекста, но не в интерфейсе.
