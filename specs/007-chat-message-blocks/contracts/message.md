# Контракт сообщения ассистента

Протокол потока не меняется — контракт событий остаётся тем, что описан
в `specs/006-chat-agent-tools/contracts/stream.md`. Меняется только то, как
интерфейс их складывает.

## Было

```
сообщение = {
  text:    "весь ответ одной строкой",
  steps:   [вызов, вызов],          ← рисуется в начале сообщения
  charts:  [ключ],                  ← рисуется в середине
  sources: [ссылка, ссылка],        ← рисуется в конце
}
```

Три отдельных списка, каждый в своём фиксированном месте. Один вызов оказывается
разорван между началом и концом сообщения, порядок событий теряется безвозвратно.

## Стало

```
сообщение = {
  blocks: [
    { вид: текст,  текст: "Смотрю, что известно…" },
    { вид: вызов,  подпись: "Ищу во внешних источниках: …",
                   состояние: удался,
                   ссылки: [...], график: null },
    { вид: текст,  текст: "**По отчёту:** …" },
  ],
  разделы: ["courts"],     ← относится ко всему ответу, не к блоку
}
```

Порядок блоков — порядок событий. Результат вызова лежит внутри своего вызова.

## Правила отрисовки

- Блок вызова свёрнут по умолчанию; раскрывается по клику.
- Раскрыт не более одного вызова в сообщении: развёрнутая страница
  и развёрнутый поиск разом выталкивают текст ответа с экрана.
- Незавершённый вызов не раскрывается — показывать нечего.
- Курсор набора стоит после последнего блока и **вне разбора разметки**:
  внутри он попал бы в разбираемую строку.
- Разделы, на которые опирается ответ, и сообщение о сбое рисуются после всех
  блоков — они относятся к ответу целиком.

## Что остаётся неизменным

- События сервера, их имена и порядок.
- То, что событие `chart` несёт **только ключ**: числа интерфейс берёт
  из загруженного отчёта, и разойтись с дашбордом они не могут.
- Непотоковый ответ для программных клиентов.
