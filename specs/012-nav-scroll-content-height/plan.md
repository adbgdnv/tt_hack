# Implementation Plan: Навигация прокручивает, разбор растёт по содержимому

**Branch**: `012-nav-scroll-content-height` | **Date**: 2026-09-05 | **Spec**: [spec.md](spec.md)

## Summary

Две правки в интерфейсе, обе маленькие.

**Навигация.** Кнопка раздела перестаёт открывать подробный вид и начинает
прокручивать страницу к карточке. Чтобы было к чему прокручивать, карточки
получают якоря по ключу раздела.

**Высота.** Раскрытая полоса перестаёт задавать высоту числом и начинает
задавать потолок. Высоту внутри потолка определяет содержимое — это и есть
«по наличию контента».

Бэкенд не меняется.

## Project Structure

```
src/web/src/
  App.tsx                        правка: навигация прокручивает, а не открывает
  components/
    SectionNav.tsx               правка: подпись действия — «перейти», а не «открыть»
    ReportSection.tsx            правка: якорь по ключу раздела
  styles.css                     правка: потолок вместо высоты, отступ якоря
```

**Structure Decision**: якорь ставится на саму карточку, а не хранится реестром
координат в состоянии. Координаты пришлось бы пересчитывать на каждой смене
высоты полосы разбора — а она теперь меняется постоянно.

**Почему отступ якоря делается стилем, а не вычислением.** У прокрутки
к элементу есть штатный отступ (`scroll-margin-top`), и он живёт рядом
с карточкой. Вычитание высоты шапки в коде прокрутки означало бы, что при
правке шапки ломается прокрутка — связь, которую никто не заметит.
