# Implementation Plan: Разбор по пулу

**Branch**: `014-pool-chat` | **Date**: 2026-09-06 | **Spec**: [spec.md](spec.md)

## Summary

**Ядро.** `verify.check` начинает принимать несколько отчётов. Это не удобство,
а починка: с одним отчётом проверка помечает настоящие числа второй компании
как неподтверждённые.

**Промпт.** Рядом с `system_prompt` появляется сборка для пула: те же правила,
та же дата, те же условия сделки — но вместо отчёта одной компании готовый
вывод сравнения (244 токена против 2 511 отчётами).

**Инструменты.** `look_up` и запрос данных получают ИНН. Компанию вне пула
инструмент не молчит, а перечисляет пул — тот же приём, что уже работает
у видов графика и тем.

**Ручка.** `POST /compare/chat/stream` — тот же поток событий, что у разбора
одной компании, с `inns` вместо `inn`.

**Интерфейс.** Тот же `ChatPanel` на экране сравнения.

## Technical Context

**Language/Version**: Python 3.12, TypeScript + React

**Primary Dependencies**: без новых

**Storage**: нет; пул и переписка живут в сессии

**Testing**: pytest на ядре и потоке; интерфейс — руками по `quickstart.md`

**Performance Goals**: ответ по пулу из трёх не дольше, чем сейчас ощущается
ответ по одной компании. Замерить и назвать числом (SC-005)

**Constraints**: балла нет в контракте ручки; графиков в пуле нет

**Scale/Scope**: пул до десяти компаний

## Constitution Check

| Принцип | Как соблюдается |
|---|---|
| **I. Спека первична** | спека и замеры написаны до кода |
| **II. Ядро не знает протоколов** | `verify` и `compare` остаются чистыми функциями; ИНН в инструменте — забота `api/agent` |
| **III. Минимальная реализация** | ни одного нового правила и ни одной новой сущности: используется готовый вывод сравнения |
| **IV. Агент обращает внимание, а не выносит вердикт** | правила те же, промпт общий |
| **IV. Отсутствие данных — ответ** | пустая тема у компании пула отвечает словами |
| **V. Отбор полей** | усиливается: в контекст идёт вывод, а не отчёты |

Отклонений нет.

## Project Structure

```
src/core/
  verify.py              правка: check принимает один отчёт или несколько

src/api/agent/
  prompt.py              правка: сборка контекста для пула
  tools.py               правка: look_up получает ИНН, работает по пулу
  graph.py               правка: Context держит пул, а не одну компанию
  loop.py                правка: поток по пулу
  events.py              правка: в блоке вызова видно, у какой компании взято

src/api/main.py          правка: POST /compare/chat/stream

src/web/src/
  App.tsx                правка: разбор на экране сравнения
  api.ts                 правка: поток по пулу
  components/ChatPanel.tsx   правка: режим пула
  styles.css             правка: разбор под сравнением

tests/
  test_pool_chat.py      ← новый
```

**Structure Decision**: `Context` держит пул вместо одной компании, а не пул
рядом с одной компанией. Два способа хранить одно и то же разъезжаются:
разбор одной компании становится пулом из одного, и весь код ниже перестаёт
знать, сколько их.

**Почему вывод сравнения, а не отчёты.** Не только цена. Положив отчёты, мы
дали бы модели заново вывести порядок — и получили бы второй порядок, спорящий
с экраном. Вывод уже посчитан кодом; модель его объясняет, а не пересчитывает.

**Почему ИНН, а не название.** В наборе три разных ТЕХПРОМА с разными ИНН.
