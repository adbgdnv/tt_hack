# Веб-интерфейс «Проверка контрагента»

Рабочий статический прототип на Vite + React + TypeScript и точечных пакетах
`@alfalab/core-components`. Тема подключена отдельно из
`@alfalab/core-components-themes/corp.css`.

## Что собрано

- главная с умным поиском по ИНН, названию и ФИО руководителя, автоподсказками,
  inline-состояниями загрузки и «компания не существует»;
- история проверок в `localStorage` с безопасным `try/catch`;
- дашборд со светофором банка как источником истины, шестью блоками и отдельными
  ориентирующими мини-индикаторами;
- финансовый SVG-график: выручка, чистая прибыль, оси, легенда и нулевая линия;
- панель сценарного чата с тремя вопросами, этапами прогресса, имитацией стриминга,
  фиксированным контрактом ответа и кликабельными пруфами;
- модальные разборы блоков, включая состояния «данных недостаточно» и
  «у ИП такого не бывает»;
- тосты для сохранения PDF, ссылок и `.txt`, точка входа в сравнение и нижняя плашка.

Фикстуры трёх компаний находятся в `src/fixtures/index.ts`. По умолчанию приложение
полностью работает на них и не требует бэкенда. Несуществующий ИНН для проверки:
`0000000000`.

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # статическая сборка в dist/
```

Для разработки с HTTP API можно задать `VITE_API_BASE`, например:

```bash
VITE_API_BASE=http://localhost:8000 npm run dev
```

Клиент использует `GET /counterparties/:inn` и
`GET /counterparties/search?q=...`. Сокращённый ответ текущего API адаптируется к
интерфейсу, а отсутствующие поля остаются честными пустыми состояниями. `POST /chat`
не вызывается: чат сценарный и хранит память только в состоянии React.

## Заглушки

- PDF, постоянные ссылки и `.txt` показывают тост, но не создают файл;
- сравнение ограничено точкой входа и счётчиком до двух компаний; отдельный экран — TBU;
- fallback в ЕГРЮЛ и уведомление о готовности отмечены как V2.
