# Counterparty Checker Constitution

ИИ-агент проверки контрагентов — кейс хакатона «Альфа Будущее» (Альфа-Банк).
Агент разбирает отчёт о контрагенте, обращает внимание на риски и отвечает на
уточняющие вопросы **только по входным данным**.

## Core Principles

### I. Спека — первична

Сначала предложение и спека, потом код. Крупные блоки (каркас, ядро, агент, фронт)
проходят через `/speckit-specify` → `/speckit-plan` → `/speckit-tasks` →
`/speckit-implement` → `/speckit-converge`. Спека — живой артефакт: поведение,
интерфейсы, edge cases. Мелкие правки идут мимо церемонии — до финала считанные
дни, и процесс не должен съедать время.

### II. Ядро не знает про протоколы

Бизнес-логика живёт в `src/core` и не импортирует ни HTTP-фреймворк, ни MCP.
Приложения `src/api` и `src/mcp_server` содержат только вызовы в ядро. Проверяется
механически: удали одно приложение — второе работает; поиск импортов приложений
внутри `src/core` не даёт совпадений. Пакетом устанавливается только `core`.

### III. Минимальная реализация

Минимальная реализация, которая закрывает требование. Скоуп внутри изменения не
расширяется: нашли смежную проблему — заводим новую фичу. Каждая задача проверяема:
тест, запрос или ручной сценарий. Ссылки на доказательства — `файл:строка` в коде.

### IV. Требования кейсодателя — закон

- **Светофор банка — единственный источник истины.** Свой скоринг не строим,
  объясняем готовый.
- **Агент рекомендует, а не выносит вердикт.** Обращает внимание человека;
  формулировки уровня «не заключать договор» — за рамками.
- **Отсутствие данных — это ответ.** Нет судебных дел → «невозможно оценить по
  этому критерию», а не «рисков нет». В коде: `None`, а не `0`.
- **Без рейтинговых таблиц.** При сравнении нескольких компаний — вывод «с кем
  лучше не общаться», без скоринговой таблицы.
- **Один режим** — «анонимный предприниматель», интересны все блоки отчёта.
- **Графики обязательны** — названы дырой текущего продукта.
- Память — в рамках одной сессии; между сессиями не храним.
- Прогресс обработки в интерфейсе показывать надо.

### V. Отбор полей — условие работоспособности

Сырой отчёт — от 1 500 до 79 500 токенов при лимите Groq 8 000 токенов/мин.
Слой отбора полей в ядре обязателен с самого начала: без него самый тяжёлый отчёт
не проходит, батч из десяти компаний невозможен. Обёртки `{"$numberLong": "..."}`
разворачиваются в числа — именно в них самые крупные суммы.

## Технологические ограничения

| Слой | Чем |
|---|---|
| Ядро | Python 3.12, чистая логика без внешних протоколов |
| HTTP | FastAPI + uvicorn, порт 8000 |
| MCP | `mcp` (FastMCP), порт 8001 — каталог `src/mcp_server`, не `mcp` |
| Фронт | Vite + React + TS, `@alfalab/core-components`, порт 5173 |
| Модель | `openai/gpt-oss-20b` через Groq; запасной — OpenRouter |
| Запуск | docker-compose, локально и на Timeweb |

- Весь продуктовый код под `src/`. В приложениях нет бизнес-логики.
- `core/config.py` — пути и `.env` без внешних зависимостей: загрузка данных не
  тянет HTTP-клиент.
- Groq требует заголовок `User-Agent` (иначе Cloudflare 403). `gpt-oss-20b`
  отдаёт поле `reasoning` — пользователю не показываем, в бюджет токенов кладём.
- Базовый URL модели — переменная `LLM_BASE_URL`; смена провайдера не трогает код.
- Данные кейсодателя — в `docs_alpha/` вне репозитория, подключаются симлинком
  `data`. 200 компаний (JSON и CSV — разные наборы). 50 из 200 — ИП: нет
  отчётности, учредителей, уставного капитала.

## Рабочий процесс

- Одна фича = одна связная поставка, ветка `NNN-<глагол-kebab>`.
- `/speckit-analyze` вместо ручной валидации формата; `/speckit-converge` — пока
  не отчитается `Converged`.
- Задачи в `tasks.md` отмечаются `- [x]` по мере выполнения.
- CI (`ruff` + `pytest`) должен быть зелёным перед merge.
- `.env`, `temp/`, `data/`, `__pycache__` в `git status` не появляются.
- Контекст в агент — только релевантные файлы: конституция + спека фичи как якорь.

## Governance

Конституция важнее прочих практик. Правки — через PR с обоснованием. Каждый PR
проверяет соответствие: границу ядра, минимальность реализации, требования
кейсодателя. Усложнение обосновывается явно.

История миграции с OpenSpec и завершённый каркас — в `docs/history/`.
