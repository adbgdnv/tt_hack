# Vibe Debug

`vibe-debug` — рабочий процесс визуального и функционального ревью через
коммент-превью. Оверлей накладывается на страницу в рантайме; исходники им не
меняются. Комментарии хранятся как структурированные данные и становятся
задачами на код только после явной просьбы пользователя.

Портирован из проекта `lapki`. Общий сервер этого инстанса:
`https://tt-hack-review.72.56.16.44.sslip.io/` (Nginx Basic Auth + systemd
`tt-hack-vibe-debug`). Развёртывание — `docs/VIBE-DEBUG.md`.

## Текущая реализация

- Вертикальная стеклянная панель с режимами `view`, `dev`, `vibe`. Стоит справа,
  перетаскивается за grip, фон и края; позиция, псевдоним, цвет и толщина кисти
  сохраняются только в текущем браузере.
- `view` выбран при каждой загрузке. Страница пассивна: без picker, cursor-comment,
  пинов, пометок и контролов изменения. Иконка списка открывает read-only очередь
  комментариев со всех маршрутов превью; бейдж считает все активные записи.
  Карточка ведёт на `ROUTE?vibe-comment=DBG-ID` — страница прокручивается к
  сохранённому selector и обводит объект. Нативные ссылки: Cmd/Ctrl-клик,
  средняя кнопка, история браузера работают.
- `dev` стартует сразу в инспекторе структуры: вложенный DOM-выбор, устойчивый
  CSS-селектор, breadcrumb, полный список и статусы. `data-debug-id` блокам
  проставляется автоматически по `.section__id`, заголовку или `id`.
- `vibe` держит нерешённые комментарии компактными пинами в сохранённой
  target-relative точке; пин открывает карточку рядом с объектом. Инструмент
  комментария — синий cursor-comment: клик фиксирует точку и DOM-объект без
  dev-подсветки.
- В `vibe` есть карандаш (штрих на едином canvas всей страницы, `selector: :root`,
  page-relative геометрия) и прямоугольная рамка (привязана к DOM-объекту,
  target-relative). Оба хранят цвет и толщину в CSS-пикселях.
- Штрихи и рамки выбираются, перетаскиваются, двигаются стрелками и удаляются
  кнопкой или `Delete`. Изменение геометрии обновляет `updatedAt` и добавляет
  `geometry_changed` в историю.
- `Cmd+Z` / `Ctrl+Z` вне полей ввода отменяет последнее создание, удаление или
  перемещение пометки; в полях ввода — нативная отмена набора.
- Учётная запись остаётся в `author`; редактируемый браузерный псевдоним
  хранится отдельно в `displayAuthor` и показывается в UI.
- Формы `dev` и `vibe` принимают PNG, JPEG, WebP скриншоты файлом или вставкой
  из буфера. Загрузка вставляет `[скриншот#ID]` в позицию курсора; комментарий
  хранит URL вложения, MIME, размер и размеры изображения. До 8 МБ, максимум 6.
- Комментарии — `comments.json`, пометки — `marks.json`, скриншоты —
  `attachments/`; всё общее между авторизованными ревьюерами на сервере.
- Карточки в `dev` и `vibe` имеют `×`, безвозвратно удаляющий комментарий через
  review API вместе с пином. Очередь `view` — read-only.

## Карта реализации

- Поведение UI: `preview/assets/vibe-debug.js`.
- Стили UI: `preview/assets/vibe-debug.css` (подтягивается самим js).
- Стили каркаса превью: `preview/assets/wire.css`.
- Страницы под ревью: `preview/*.html` (подключают `vibe-debug.js` тегом
  `<script>` напрямую — общего загрузчика нет).
- API и атомарные JSON-хранилища: `scripts/vibe_debug_server.py`.
- Тесты хранилищ и схемы: `tests/test_vibe_debug_server.py`.
- Валидатор схемы: `scripts/review_schema.py`.
- Read-only аудит данных: `scripts/audit_vibe_debug_data.py`.
- Карточки разбора: `scripts/review_triage.py`.
- Локальный запуск: `python3 scripts/vibe_debug_server.py`; общий превью:
  `https://tt-hack-review.72.56.16.44.sslip.io/`.
- Локальные данные: `.vibe-debug/`. Данные сервера:
  `/opt/tt-hack-review/` — не заменять при выкладке статики или кода.

API маленький намеренно: `GET /__review__/comments` отдаёт очередь всего сайта,
`GET /__review__/comments?route=/report.html` — один маршрут. Запись
(комментарий, статус, удаление, вложение, пометка) — POST-роуты из
`docs/VIBE-DEBUG-RUNBOOK.md`.

## Правила безопасности

- Цель по умолчанию — локально.
- Общий сервер — после того, как пользователь просит опубликовать или посмотреть там.
- Production не меняется из этого скилла без явного подтверждения в текущем разговоре.
- `main` защищён: не пушить и не деплоить молча.
- Никогда не класть в Git пароли, токены, SSH-ключи, значения `.env` или
  содержимое `.htpasswd`. В репозитории — `.env.example` и шаблоны; секреты — на
  сервере.
- Не ставить `resolved` до проверки правки в том же превью.

## Режимы вызова

### Поднять превью

При `/vibe-debug` без запущенного превью:

1. Прочитать `case_info.md`, `docks/` (product, architecture, roles), `README.md`
   и `docs/VIBE-DEBUG-RUNBOOK.md`.
2. Осмотреть текущую ветку и рабочее дерево.
3. Проверить, жив ли общий сервер:
   `curl -sfu USER:PASS https://tt-hack-review.72.56.16.44.sslip.io/__review__/comments`.
   Жив и здоров — не поднимать второй, вернуть URL и маршрут.
4. Локально при необходимости: `python3 scripts/vibe_debug_server.py`
   (`VIBE_DEBUG_PORT`, `VIBE_DEBUG_ROOT`, `VIBE_DEBUG_DATA`). Дать точный URL.
5. Если просят опубликовать на сервере — сначала пройти проверки контура.

### Продолжить запущенное превью

Вернуть точный маршрут запрошенной страницы/блока/компонента или всего сайта.
Для статической страницы — сохранённый HTML-маршрут. Не плодить серверы, если
существующий здоров.

### Разбор комментариев (triage)

Шаг между комментарием и кодом. Запускать, когда просят разобрать очередь —
продуктовые файлы не трогает.

1. Снять read-only снимок очереди и прогнать `scripts/audit_vibe_debug_data.py`.
   Стоп на любой ошибке.
2. Прогнать `scripts/review_triage.py` в `docs/review/<дата>-<область>.md`.
3. Заполнить каждую карточку: класс (`content` / `ux` / `scope` / `question` /
   `bug` / `fyi`), что понято и что нет, затрагиваемые файлы, промпт исполнителю.
4. Строку `Решение:` оставить пустой — её пишет человек.
5. Отчитаться: файл карточек, счётчик по классам, всё, что не удалось
   классифицировать без ответа.

### Применить комментарии

Только когда пользователь говорит применить / закрыть / починить, **и** в
карточке есть строка `Решение:` от человека.

1. Перечитать карточку и исходную запись. Расходятся — стоп и вопрос.
2. Перевести комментарий в `in_progress` через review API.
3. Внести минимальную связную правку. Пояснительные комментарии в код не добавлять.
4. Прогнать `python3 -m unittest discover -s tests` (если трогали сервер/схему),
   затем smoke-тест затронутого маршрута на 375 и 1440.
5. `resolved` — только когда правка видна в том же превью; `wont_fix` — с
   причиной для отклонённых.
6. Отчитаться: изменённые файлы, ID комментариев, URL превью, тесты, контур,
   нерешённые риски.

## Схема комментария

Единственная схема — `schemas/vibe-debug-comment.schema.json`, этот файл её не
повторяет. Пишет `normalize_comment()` в `scripts/vibe_debug_server.py`,
проверяет `scripts/review_schema.py`, гоняют `scripts/audit_vibe_debug_data.py`
и тест `test_stored_comment_matches_published_schema`. Менять схему — значит
менять сервер, схему и тест одним коммитом. Записи до текущей схемы задним
числом не переписываются (легитимно без `mode`, `displayAuthor`, `anchor`,
`attachments`, `updatedAt`).

## Жизненный цикл

`new` → `approved` → `in_progress` → `resolved`; терминальный отказ — `wont_fix`
с причиной. Legacy-очереди могут содержать `done` — считать за `resolved` только
после проверки правки.

Комментарий — вход, а не задача. Конвейер зафиксирован в
`docs/REVIEW-TO-TASK.md`:

```text
DBG-*  ->  карточка разбора  ->  решение человека  ->  промпт  ->  правка  ->  проверка  ->  resolved
```

Шаг одобрения не пропускать: карточку пишет агент, строку `Решение:` — только человек.

Минимальная графическая пометка:

```json
{
  "id": "VIBE-stable-id",
  "kind": "stroke",
  "route": "/report.html",
  "selector": "[data-debug-id=s-risks]",
  "author": "dbndrnk",
  "displayAuthor": "Даша",
  "style": {"color": "#a96f7b", "thickness": 6},
  "geometry": {
    "coordinateSpace": "target-relative",
    "points": [{"x": 0.1, "y": 0.2}, {"x": 0.4, "y": 0.5}]
  },
  "updatedAt": "ISO-8601",
  "history": [{"at": "ISO-8601", "by": "dbndrnk", "action": "created"}],
  "target": {
    "selector": "[data-debug-id=s-risks]",
    "element": "section",
    "label": "Что нашёл агент",
    "excerpt": "Массовый адрес регистрации"
  }
}
```

## Аутентификация

Локальное превью может быть без аутентификации. Тест и прод — за Nginx Basic
Auth. Ревьюеры: `dbndrnk`, `poulyak`, `adbgdnv`. Пароли — только в
`/etc/nginx/htpasswd/tt-hack` на сервере или в окружении деплоя. В репозитории —
шаблон Nginx и имена переменных, никогда не хэши и не пароли.

## Обязательный отчёт

Каждый вызов заканчивается компактным отчётом:

- цель и URL;
- действие: поднял, сроутил, обработал, заблокирован;
- изменённые файлы и закрытые ID комментариев;
- проверки и smoke-тесты;
- ветка и коммит;
- нерешённые вопросы и риски.

Детальная операционка — `docs/VIBE-DEBUG-RUNBOOK.md`.
